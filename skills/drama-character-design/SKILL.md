# 短剧/漫剧原创 IP 角色设计

## 何时使用

用户要为短剧/漫剧/漫画/视觉小说设计**原创 IP 角色**或为已有角色制作设定图，包括：

- 原创角色定位、IP 角色概念设计（要辨识度、要能立得住）
- 角色定妆照、主角/配角设计
- 三视图 / turnaround 转面参考（正 / 3/4 / 侧 / 背）
- 表情表（expression sheet）
- 服装表（同角色多套造型）
- 角色色板、角色一致性参考
- 泛化的"设计一个人物 / 这个角色要有记忆点 / 系列里不能认错人"需求

**分镜、剧本拆解、视频脚本不在本 skill 范围**；场景/世界观设计走 drama-scene-worldview skill，两者配合使用。

## 角色定位与辨识度（原创 IP，先于一切 prompt）

本 skill 的核心目标不是"画得好看"，而是**设计出有辨识度、能成为 IP 的角色**。借鉴角色设计通行方法论（剪影测试 / 色彩记忆点 / 标志性记号），在写任何提示词之前先完成定位：

- **一句话人设定位**：身份 + 性格 + 剧功能（"毒舌但护短的酒吧老板娘"）——由 ask_user 收集或从剧本提取，它是后续所有表情/姿态/服装选择的依据
- **辨识度三件套**（每个角色必须齐备，写进锚点）：
  1. **剪影（silhouette test）**：涂黑后仍能一眼认出是 TA——靠发型外轮廓、体型、标志道具/服饰。方案要自问"涂黑能不能认出"
  2. **色彩记忆点**：主色 ≤2 个且全剧专属（登记进世界观色板的角色配色编码），别人画这张角色时也用这对色
  3. **标志性特征**：1–3 个可复述的视觉记号（泪痣 / 异色瞳 / 断刀 / 红围巾 / 机械臂……）——标准是"别人介绍这个角色会说出的那句话"
- **差异化检查**：`recall_memory` 查项目已有角色 bible，新角色与每个已有角色两两对比——剪影轮廓、主色、标志特征**不得撞车**；同剧角色放一起必须一眼分得清
- **防 AI 俗套脸**：默认生成的"精致网红脸"没有辨识度；特征要具体到可画（"左眼下泪痣 + 右眉断眉"），不要停留在"好看的"
- **给方案而非等答案**：定位明确后，agent 主动提出 2–3 套辨识度方案（各自的剪影逻辑 / 主色 / 标志特征 + 一句推荐理由），用户选定或改写后才算定稿

**定稿之前不写锚点、不建节点**。用户带参考图来时，辨识度三件套从参考图提取并向用户确认。

## 角色身份锚点（Identity Anchor）—— 定稿后写提示词前必做

借鉴 inference-sh/character-design-sheet 的 description anchor 技法 + nexu-io/ecommerce-image-workshop 的 identity lock。在写任何提示词之前，先从用户上传的参考图（或口头描述 + ask_user 提问）提取并锁定**角色描述锚点**，后续每条 prompt **逐字复用**，只换动作/镜头/场景：

- **年龄段**：具体到区间（"二十五六岁"），禁用"年轻""中年"等模糊词
- **发型发色**：发型 + 发长 + 颜色（词 + hex，如"茶褐色短发 #6b4a2f"）
- **瞳色 / 肤色**：词 + hex
- **面部固定标记**：痣、疤、雀斑、泪痣等不可变特征（无则写"无特殊标记"）
- **标志性特征（辨识度三件套）**：剪影逻辑（发型外轮廓/体型/标志道具）、专属主色（≤2，hex）、1–3 个标志记号——逐项显式写入
- **服装逐件描述**：上装 / 下装 / 鞋 / 配饰，每件带颜色与款式（模型会自行"补全"未描述的衣物细节，是服装漂移的主因）
- **体型与头身比**：见下方比例表
- **不可变项清单（must not change）**：发型发色不得变化、面部标记不得增删、服装件数不得增减、配色不得偏色、年龄感不得漂移

锚点 50 字以上、一段成文。**不可省略**；无参考图且描述不足时先 ask_user / 索取，不要凭角色名脑补。

### 头身比参照（借鉴 inference-sh）

| 风格 | 头身比 | 适用 |
|---|---|---|
| 写实 | 7.5 : 1 | 真人感短剧 |
| 英雄 | 8 : 1 | 动作/热血向 |
| 日漫 | 5–6 : 1 | 日式漫剧 |
| 美式 | 4–5 : 1 | 西式动画 |
| Q版 | 2–3 : 1 | 萌系/搞笑番外 |

比例写进每条 prompt（如"5.5 头身日漫比例"）。

## 设定集类型与基准图策略

| 类型 | 内容 | 说明 |
|---|---|---|
| 定妆照 / 正视图 | 全身正面站姿、中性表情、干净背景 | **基准图**，优先生成 |
| Turnaround | 正 / 3/4 / 侧 / 背 四视图 | 同锚点只换视角词 |
| 表情表 | 中性 / 喜 / 怒 / 哀 / 惊 / 思 ≥6 种 | 特写构图，同锚点只换表情词 |
| 服装表 | 常服 / 剧内主造型 / 特殊场合 | 逐件描述每套 |
| 色板表 | 肤 / 发 / 瞳 / 主服装 / 点缀色 | 记录精确 hex，防跨图漂移 |

- **正视图（或定妆照）作基准图**，其余视角 / 表情 / 换装图全部衍生自它
- 用途分流：短剧定妆 → 定妆照 + 表情表（+ 换装表若剧情需要）；漫剧 → turnaround 全套 + 表情表；单张需求 → 说明为何选该类型
- 需求模糊时默认给：正视图 + 3/4 侧 + 1 张表情表，并说明这是默认组合

## 执行步骤

1. **角色定位（原创 IP 前置）**：ask_user 收集一句话人设 / 剧功能 / 参考偏好；`recall_memory` 查已有角色做差异化检查；提出 2–3 套辨识度方案（剪影逻辑 / 专属主色 / 标志特征 + 推荐理由），**用户确认定稿后才进下一步**
2. **锁角色身份锚点**：定稿方案 + 参考图（如有）合并写成一段内部锚点；有参考图从图提取，描述不足处 ask_user 补全
3. **补全缺失信息**（ask_user 结构化选项 + 其他可编辑，一次性问全；用户 waived 或信息已够后不再追问）：
   - **画风**：A 写实 / B 日漫 / C 国漫 3D / D 美漫 / E 厚涂插画 / 其他（请说明）
   - **头身比**：按上表给选项（可依画风自动推荐默认值）
   - **用途**：A 短剧定妆 / B 漫剧设定集 / C 单张立绘 / 其他（请说明）
4. **按用途分流设定集类型**：查"设定集类型与基准图策略"
5. **建节点 + 写 prompt**：用 `upsert_media_node` 创建 image 节点；每条 prompt 顶部带 fidelity lock 段落（保持参考图角色身份不变：五官、发型发色、瞳色、肤色、面部标记、标志特征、服装件数与位置、头身比；不得重新设计角色；不得增删或移动角色特征），随后**逐字复用锚点**，再按"动作/表情/镜头 → 光线 → 质量词"展开；每类图可给 1–3 个变体标推荐项
6. **挂参考图（数据层）**：侧栏参考图用 `apply_sidebar_attachments`（mode=localRefs，@I* 芯片序）；画布已有图才用 `attach_refs`；ref 顺序先角色基准图，后场景/其他
7. **连视觉边（视觉层）**：`connect_nodes` 以正视图/定妆照为 source，其余视角 / 表情 / 换装图各自有向边指回基准图，表达"从基准衍生、保持角色一致"
8. **自动分层**：`arrange_nodes(along_edges)` 让基准图居左、衍生图向右展开
9. **提议生成**：`propose_generation` 提议生成，等待用户确认；确认前不调用 `run_*`
10. **出图后 QA 闸门 + 定位**：先 `focus_node` 定位到新节点，再对照 QA 闸门自检并报告 PASS/REVISE/REJECT
11. **登记角色档案**：QA 通过后用 `save_memory` 存角色 bible（一句话人设 + 辨识度三件套 + 锚点全文 + 色板 hex + 画风关键词 + 头身比 + 画布基准节点 id），后续会话 `recall_memory` 直接复用，防跨会话重设

## 出图后 QA 闸门

借鉴 omer-metin/art-consistency（"Reference 是合同、每张必过 QA、风格漂移防大于治"）：

- **Gate 1 辨识度**：剪影是否成立（遮脸仍认得出）、专属主色是否醒目、标志特征是否清晰可见——辨识度是本 skill 的第一交付物，不达标即 REVISE
- **Gate 2 角色一致性**：五官 / 发色 / 瞳色 / 肤色 / 面部标记 / 标志特征 / 服装件数 / 头身比是否与锚点一致；任何一项走样即 REVISE
- **Gate 3 设定集规范**：turnaround 视角是否标准、表情是否到位、背景是否干净、全身构图是否完整
- **Gate 4 无虚构**：不得出现锚点以外的服饰 / 配饰 / 武器 / 纹身等设定外元素；不得改年龄感
- **Gate 5 套图一致性**：同角色在不同图里同一视觉世界（画风 / 光照 / 线条风格统一）

**评审结论**：PASS 交付 / REVISE 局部重画（指出哪一 gate 哪一项）/ REJECT 整体重做。REVISE/REJECT 时不虚构已修复，回到 step 4 重新写 prompt。

## 常见翻车对照表（借鉴 inference-sh）

| 翻车 | 原因 | 对策 |
|---|---|---|
| 路人脸 / AI 网红脸 | 只写"好看""精致" | 标志特征具体到可画，写进 prompt 前段 |
| 角色互相撞脸 | 剪影/主色/标志物趋同 | 定位期做差异化检查；主色全剧专属 |
| 发色漂移 | 模型每次解读"红发"不同 | 写具体色名 + hex："茶褐 #6b4a2f" |
| 瞳色变化 | 生成权重低 | 瞳色写进 prompt 前段 |
| 服装不一致 | 模型自行补全细节 | 逐件显式描述，不留白 |
| 年龄漂移 | "年轻"太模糊 | 写"二十五六岁"这类区间 |
| 脸型变化 | 逐次生成累积漂移 | 锚点逐字复用 + 基准图 ref |
| 头身比漂移 | 风格解读波动 | prompt 显式写"5.5 头身" |

## 与剧本、场景 skill 的配合

- **上游是 drama-script-writing**：剧本 IP bible（logline / 主角三角 / 人物名录）经 `recall_memory` 取用——主角三角是人设定位与表情姿态的依据；剧本给出的人物首次出场描述是锚点的起点
- 角色出镜的场景图（drama-scene-worldview skill 产出）：prompt 必须携带本角色的**锚点原文**，并 `attach_refs` 挂角色基准图为参考
- 画风以项目已确立的风格圣经为准（先建立者有效，后建立者跟随）；各 skill 登记的 bible 通过 `recall_memory` 互查

## 规则与边界

- 不虚构已出图；确认前不调用 `run_*`
- 芯片 key（@I1/I2）不是画布节点 id；禁止 `connect_nodes` 连芯片
- **锚点不可省略**，且**必须在定位定稿之后**写；无参考图且描述不足先问，不脑补
- 辨识度三件套缺一不可；用户只说"画个帅哥/美女"时先做定位提问，不直接出图
- 按用户意图动态选型：用户没要的类型（换装表 / Q 版形象）不要自作主张加入
- 每类图可给 1–3 个变体标推荐项；每个变体都要有完整 prompt
- **分镜拆解、剧本、视频脚本、图生视频不在本 skill 范围**（剧本见 drama-script-writing、分镜见 drama-storyboard）

## 提示词写法

- **fidelity lock 段落**（每条 prompt 顶部必带）→ **锚点逐字复用** → 动作 / 表情 / 镜头 → 光线 → 质量词；结构固定，只变场景变量——同一结构换着强调会带来随机变化
- **标志性特征必须显式出现在每条 prompt**（"左眼下泪痣、红围巾"），不看参考图的图靠它维持辨识度
- 画风关键词全项目统一（如"日漫赛璐璐、干净线条、锐利细节"），写进锚点尾部的 Style Keywords
- 人物性格落到表情/姿态语义（"自信但亲和、默认浅浅好奇的微笑"），供表情表与演出图选用
- 显式声明不得出现的元素（无水印、无设定外服饰、无文字拼贴）
