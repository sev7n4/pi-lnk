# 分镜 → 视频（图生视频 / motion 提示词）

## 何时使用

用户要把分镜静帧变成视频，包括：

- 静帧 → 视频（图生视频）、动态分镜
- motion 提示词、运镜设计、动作描述
- 首末帧配对（给终点状态）
- 用已生成视频的末帧**续接**延长同一镜
- 泛化的"这几张分镜怎么动起来"需求

**成片剪辑 / 合成 / 发布不在本 skill 范围**（平台无该能力，见 drama-qc-review 的交付说明）。上游：drama-storyboard（镜头表 + 已生成静帧 + 参考绑定）。

## 铁律：静帧不成立的镜头，做不成好动图

- **先获批静帧再上视频**——构图、色彩、身份在静帧阶段改最便宜；静帧阶段就不对，动起来只会更糟
- **图管外观，prompt 管时间**：静帧已经定义了主体、构图、光线、风格；prompt **只写"什么在变"**。重述画面细节会诱导模型重新解释这一帧

## motion 提示词结构（六段，顺序固定）

借鉴 Blyth 五层公式 + aicraft 的 frame lock / subject lock 框架：

1. **Frame lock**：以上传静帧为精确首帧，构图与画面内容不变
2. **Subject lock（不变量）**：身份 / 面部 / 服装 / 道具形状与状态 / 构图 / 背景保持不变
3. **Camera（一个运动 + 速度）**：只写**一个**相机运动（见词表），带方向与速度（缓慢 / 匀速 / 轻微）
4. **Action（一个主导动作）**：主体一个可读的动作，速度与重量感真实
5. **环境次运动**：仅必要项——发丝、衣摆、反光、烟尘、雨、光斑
6. **Prohibitions**：禁止变形 / 新增物体 / 文字变形 / 跳切 / 手部与面部崩坏 / 背景替换

**相机语言与主体动作必须分开写**：混在一句里模型会自己编两样，通常编得很差。

### 相机运动词表（与 drama-storyboard 镜头表一致）

| 运动 | 情感意图 | 风险提示 |
|---|---|---|
| push in 推进 | 亲密、紧张、聚焦 | 最稳，适合首测 |
| pull back 拉远 | 揭示尺度、孤立 | 需模型编造画面外区域 → 变化更大 |
| pan 横摇 | 揭示相邻环境、跟随 | 须说明主体是否保持居中 |
| tracking 跟拍 | 与主体同行、保持构图 | 与主体动作配合，别同时加大动作 |
| orbit 环绕 | 强调主体、建立体积感 | **从小角度起步**（15° 级），360° 全转必形状漂移 |
| crane 升降 | 宏大揭示、转场 | 高成本，慎用 |
| handheld 手持 | 紧迫、纪实 | 与稳定构图冲突，不要同镜混用 |
| fixed 固定 | 静定、专注 | 反转前的静默镜头首选 |

## 时长与参数策略

- **时长按运动复杂度取最短**：4 / 5 / 10 / 15 秒四档；**越长越容易身份与几何漂移**。一个镜头只完成一个信息点，别让一条生成承担整场戏
- 短剧默认 **9:16 竖屏**；`resolution` 与 `crop` 按项目统一（同剧不要混比例）
- **运动强度**：低 = 保身份、纪录片感；中 = 商业感；高 = 戏剧但**易毁脸与手部**。默认从中低起步，身份敏感镜（角色特写）用低
- ⚠️ `generateAudio`（部分视频模型自带音频，默认 true）：开启会与 drama-audio-design 的 TTS 配音**双重人声** → 二选一，项目级统一。若开视频自带音频，配音环节只做补充与旁白

## 首末帧配对与续接（最有效的确定性手段）

- 需要**终点状态可预期**时给末帧（平台有 `lastFrameUrl`）：转身、揭晓、变形、转场、循环——模型在已知两态之间插值，mid-clip 意外大幅减少
- **续接延长**：用上一条成片的**末帧**作下一段首帧，比拿原始静帧再生成更稳（同一镜延长、时序连续）；平台会把末帧存回节点（`lastFrameUrl`）
- 无末帧时：口头给出终点描述（"镜头结束时她已转身面向窗"），并接受较高变数

## 工作流（先便宜后昂贵）

1. **取上游**：镜头表（景别/角度/运动/时长/Action/Blocking）+ 已获批静帧 + 该镜的参考绑定
2. **写 motion prompt**：按六段结构；相机运动照抄镜头表的运动与动机，保持一致
3. **便宜测试**：每镜先出**最短时长 + 中低强度 + 单 seed** 的一条，目的只是裁决"这张静帧配这个 prompt 行不行"；漂了就改静帧或改 prompt，别急着加时长
4. **批量出 take**：通过后按真实时长、多 seed 出几条
5. **审看方式**：**全速播放**看，不逐帧看——运动问题只在播放时可见
6. **延长与变体**：需要更长用末帧续接；需要备选就换 seed 重出，别改 prompt 与参数混在一起（无法归因）
7. **定位**：`focus_node` 让用户第一时间看到结果

## 与音频的接缝

- 若视频开启 `generateAudio`：本 skill 直接产出带音频的镜头，配音环节不再为该镜出 TTS
- 若关闭：由 drama-audio-design 逐镜出 TTS 音轨，音画对齐在那边定义（J-cut / L-cut / 静默点）
- 时长必须先于配音确定：**镜头时长是配音语速的硬约束**（中文约 4–5 字/秒）

## QA 闸门

- **Gate 1 不变量**：主体身份 / 面部 / 服装 / 道具形状与状态 / 构图 / 背景是否与静帧一致；任何漂移即 REVISE
- **Gate 2 运动契约**：相机运动是否与镜头表一致；主体动作是否单一可读；相机与主体是否在争注意力（争了就拆镜）
- **Gate 3 生成缺陷**：无跳切、无新增物体、无文字变形、无手部与面部崩坏、无意外背景替换
- **Gate 4 时长与节奏**：是否在镜头表给的时间格内完成该 beat；有无"长时长空转"
- **Gate 5 首末帧契约**：给了末帧的镜头，结尾状态是否到达指定末帧

**评审结论**：PASS 交付 / REVISE 局部重出（指出哪一 gate）/ REJECT 回到静帧重做（静帧本身不合格）。不虚构已生成。

## 常见踩坑对照表

| 踩坑 | 后果 | 对策 |
|---|---|---|
| prompt 重述画面细节 | 模型重解释这一帧，身份/风格跳变 | 只写变化（图管外观、prompt 管时间） |
| 相机与动作混成一句 | 两样都被模型乱编 | 分开写，各一句 |
| 静帧本身有运动暗示 | prompt 要求的运动与画面冲突（如静物却有大片灰尘） | 先修静帧或改用图生图去暗示 |
| 同时推进 + 大动作 | 画面失控 | 首测让相机承担能量，主体动作减小 |
| 360° 环绕 | 主体形状漂移 | 从小角度（15°）起步 |
| 时长拉满 | 身份漂移、无意义空转 | 取完成镜头所需的最短时长 |
| 逐帧审片 | 看不出运动问题 | 全速播放审看 |
| 开 generateAudio 又配 TTS | 双重人声 | 项目级二选一 |
| 一次改 prompt + 参数 + seed | 无法归因 | 每次只改一个变量 |

## 规则与边界

- 不虚构已生成；`propose_generation` 确认前不调用 `run_video_generation`
- 生成耗时长（约 11 分钟/条），**批量与重出要有节制**：先便宜测试、再批量
- 静帧未获批不上视频；本 skill 不负责改静帧（回 drama-storyboard）
- **成片剪辑、合成、发布、配乐生成不在本 skill 范围**
