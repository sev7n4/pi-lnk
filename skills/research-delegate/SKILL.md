# 调研委派子代理（research-delegate）

## 何时使用

任务同时满足两条才派发，缺一自己做：

1. **只读调研**：调研/研究/探索/多源核对/联网查资料——过程中不需要改画布、不需要生成内容、不需要问用户；
2. **探索过程不值得占主窗口**：中间翻页、核对、试错不产出用户可见的进展，只有最终结论有价值。

典型形态：技术方案对比、竞品/资料盘点、多源事实核对、画布上下文摸底（现状梳理后给建议）。

## 派发前检查（两条红线，命中即不派）

- 任务要**改画布 / 生成内容 / 操作节点 / 问用户**？→ 不派，自己做。子代理白名单物理只读，派了也做不了。
- 探索过程本身用户想看着走？→ 不派（如教学式逐条分析），直接在主窗口做。

## task 三段写法（对应 spawn_subagent 三个参数）

| 参数 | 写什么 | 反例 → 正例 |
|---|---|---|
| `task` | **要查什么**：核心问题清单，越具体越好 | ✗「调研 WebSocket」→ ✓「对比 WebSocket 与 SSE：协议特性/断线行为/代理兼容性/适用场景四维度」 |
| `background` | **背景补充**：已读过什么、已试过什么、相关约束 | 「用户画布上已有 SSE 方案的节点，重点补 WebSocket 侧」 |
| `reportFormat` | **期望的报告结构与重点**；缺省内置骨架（结论先行+来源清单+未核实标注） | 「只要一张对比表+一句选型建议」 |

不填 `reportFormat` 时系统自动注入【期望报告形态】骨架（结论先行；末尾附来源清单；无法核实的标注「未核实」）——所以**宁可让 reportFormat 缺省，也不要给含糊的形态描述**。

## mode 选择（block vs background）

- **block（默认）**：单路调研、结果马上要用来做下一步 → 直接阻塞等报告。
- **background + collect_subagent_result**：并行多路对比调研（如同时派「技术选型」「竞品盘点」两路）。派发后先做其他事（读画布/整理已有信息），**回合结束前必须 collect**——未取回的后台结果会随进程丢失（账本可取证但报告拿不回）。
- 并发上限 2：第 3 路会被拒（fail-soft），先 collect 已完成的再派。

## 结果整合纪律

1. 引用子代理结论时**保留其来源标注**；来源清单缺失的报告要明确说「该结论未经来源核验」。
2. 子代理报告与画布事实冲突时**以画布为准**（画布是用户作品的 SSOT），冲突点要向用户点出。
3. 子代理失败（ok:false）/ 报告为空：按 hint 自行联网/读文档完成调研，**不要静默放弃或假装已完成**。
4. 报告被截断（truncated:true）：结论部分完整可用，来源清单可能缺失——向用户注明。

## 工具可用性

- 主代理可用：`spawn_subagent`（常驻）、`collect_subagent_result`（常驻）；两者不在子代理白名单内（递归封死）。
- 工具不在你的列表里时先 `tool_search` 关键词「调研/子代理」。
