# 短剧/漫剧分镜包生成（剧本 → 分镜 + 参考对象）

## 何时使用

用户要把剧本转成可生成的分镜包，包括：

- 剧本解析、资产清单提取（这部剧需要哪些角色 / 场景 / 道具 / 音频）
- 分镜拆解、beat 拆解、镜头表、shot list
- 分镜提示词、镜头语言设计（景别 / 角度 / 运动）
- 道具图、配音 / 音效 / BGM 节点与提示词
- 参考对象绑定（哪个镜头该参考哪些角色图 / 场景图 / 道具图）
- 泛化的"把这段剧本变成能出图的镜头"需求

**图生视频与 motion 提示词走 drama-motion-video skill；配音与声音设计走 drama-audio-design skill；审片与一致性审计走 drama-qc-review skill；成片剪辑 / 合成 / 发布不在平台能力面**。上游：drama-script-writing（剧本 + IP bible）、drama-character-design（角色图）、drama-scene-worldview（场景图）。本 skill 是它们的下游，也是**缺失资产的补齐者**。

## 输入契约（开工前先取）

- **剧本**：画布上的 prompt 节点（`get_canvas_summary` / 读节点正文）；无剧本时先转 drama-script-writing
- **IP bible**：`recall_memory` 取 logline / 主角三角 / 人物名录 / 世界观要点——**别让用户重述已知信息**
- **已有资产**：画布上已有的角色图 / 场景图 / 道具图 / 音频节点；查到节点 id 才能在绑定阶段引用

## 阶段一：资产解析（Asset Breakdown）

从剧本逐集提取四类资产，产出一张**资产表**（写成 prompt 节点，标题 `资产表 · <剧名>`）：

| 类别 | 提取内容 | 分类 |
|---|---|---|
| 角色 | 名称、首次出场集数·场次、剧情功能、是否有图（节点 id） | 主角 / 配角 / 群演（群演不单独建模） |
| 场景 | 场景名、内/外景、时段、出现集数、是否有图 | 主场景 / 过场场景（过场可复用主场景视角） |
| 道具 | 名称、剧情意义、涉及人物、出现集数、是否有图 | **hero prop**（剧情关键）/ **action prop**（角色使用）/ **set dressing**（环境陈设） |
| 音频 | 对白、独白（VO）、音效（SFX）、配乐（BGM 情绪） | 对白/VO **可生成**（TTS）；SFX/BGM 仅作声音设计说明 |

- 每项标注「**已有**（节点 id）/ **缺失**」——缺失才进阶段二，已有资产**不得重复生成**
- 群演、过场场景、set dressing 明确标注"不单独建模，用通用描述 + 复用主资产"，防资产表膨胀

## 阶段二：补齐缺失资产

- **角色图** → 转 drama-character-design（带上剧本给的首次出场描述与主角三角）
- **场景图** → 转 drama-scene-worldview（带上剧本给的出场标注：内/外景、时段）
- **道具图** → 本 skill 内完成，用轻量锚点（道具版身份锁）：`名称 + 材质（词+hex）+ 尺寸比例 + 固定细节（Logo / 文字 / 磨损状态 / 开合状态）+ 不可变项`；`upsert_media_node(target_type="image")` 建档，hero prop 单独出图，set dressing 并入场景图解
- **音频**：分两类，**不要混淆可生成与仅说明**（`run_audio_generation` 当前**只做 TTS 配音**）：
  - **对白 / VO（可生成）** → `upsert_media_node(target_type="audio")`：角色名 + 情绪 + 语气 + 语速 + 台词原文；VO 标注是否与画面同步（J-cut 声音先入 / L-cut 声音后出）；建节点后经 `propose_generation` → `run_audio_generation` 出音轨
  - **SFX / BGM（仅说明，无生成链路）** → 写入镜头表的 Audio 列作为**声音设计说明**（SFX：具体声音事件 + 时间点"耳光声 00:03"；BGM：情绪曲线 + 强度 + 起止点"压抑钢琴，随反转爬升，00:40 处收"），供用户或剪辑环节执行；**不得声称已生成**
- 资产补齐走 `propose_generation` 等用户确认，确认前不调 `run_*`

## 阶段三：Beat 拆解与镜头表

- **beat 拆解**：每个场景拆出**可视觉化的叙事锚点**（长剧集/漫剧标准 ≥9 beat；短剧按"钩子 → 冲突 → 反转 → 钩子"拆 4–6 镜）
- **镜头表**字段（一行一镜，顺序固定：场次+镜号 → 景别 → 角度 → 主体 → 运动）：

| 字段 | 说明 |
|---|---|
| Shot ID | `S03A` 形式（场景号 + 镜序），**每场重新起编**，不跨全剧连编 |
| Beat | 叙事目的（不是画面内容） |
| 景别 | ECU / CU / MCU / MS / MLS / LS / WS / EWS |
| 角度 | 平视 / 高角 / 低角 / 鸟瞰 / 荷兰角 / OTS（须注明"谁的肩"） |
| 运动 | static / pan / tilt / dolly / truck / crane / zoom / handheld + **动机**（揭示 / 跟随 / 权力变化…） |
| 时长 | 预估秒数 |
| Action | 画面内发生了什么变化 |
| Blocking | 人物位置、运动路径、视线方向、屏幕方向 |
| Audio | 对白 / SFX / BGM / 静默 |
| 连续性锚点 | 角色外观、道具状态、光线、服装、场景朝向 |

- **景别服务于信息量**：远景给地理关系、中景给关系与动作、特写给决策与情绪、插入给证据；**复杂运动只留给真正需要的时刻**
- **运动必须有动机**（揭示信息 / 跟随动作 / 改变权力关系 / 制造不安 / 建立尺度）——"能动就动"是新手病

## 阶段四：分镜提示词

每条分镜 prompt 按固定结构（顺序不换，防随机变化）：

1. **fidelity lock 段落**：角色锚点原文（`recall_memory` 取）+ 场景身份 + 道具状态——**连续性锚点必须写进每条 prompt，不要假设模型记得上一镜**
2. **镜头规格**：景别 + 角度 + 运动 + 镜头感（"35mm 感、浅景深""长焦压缩"）
3. **动作与调度**：谁在哪、在做什么、视线朝向（可拍动作，不写心理）
4. **光线与情绪**：光源方向 + 时段 + 色温（词 + hex）
5. **质量词**：画风关键词（与项目风格圣经一致）+ 显式排除项（无水印、无字幕、无设定外元素）

- 建节点：`upsert_media_node(target_type="image", prompt=..., title="S03A · 场景名")`
- **每镜只描述一个瞬间的变化**；一个镜头里塞两件事就拆成两镜

## 阶段五：参考对象绑定

- **数据层（决定生成时参考什么）**：`attach_refs`（画布图）/ `apply_sidebar_attachments(mode=localRefs)`（侧栏附件）；ref 顺序**先角色后场景再道具**；出镜角色镜头必挂角色基准图，场景还原镜头必挂定场图
- **视觉层（画布可见的关系）**：`connect_nodes` 从资产图连向引用它的分镜节点（角色图 → 该角色出镜的每个分镜；场景图 → 该场景的各镜）；`arrange_nodes(along_edges)` 分层展开
- **绑定检查**：每个出现角色的镜头都必须有对应 ref；同一角色的多镜用**同一张**基准图（不要各镜各挂一张不同版本）
- 参考对象**按用途路由**，不做"灵感堆砌"：构图参考 / 连续性参考（角色设定图、场景定场图、道具板）/ 负面参考（明确不要什么）；**禁止**让模型克隆在世艺术家、真实品牌、版权角色或未授权影片的具体画面

## 阶段六：音频对齐

- 音频节点与分镜节点的顺序对齐：J-cut（声音先于画面切入）/ L-cut（声音延续到下一镜）
- 静默也是设计：**关键反转前的静默点必须显式标注**，不要用 BGM 填满
- 情绪峰值位置对齐剧本的情绪曲线（剧情 skill 已定义）；峰值镜头优先给特写与静止机位

## QA 闸门

- **Gate 1 剧本忠实度**：beat 是否覆盖该场全部叙事要点；台词是否被改写（不得改动剧本台词，只做镜头化呈现）
- **Gate 2 连续性**：180° 轴线是否跨越（对话双方视线方向必须对视，不得同向）；视线匹配、屏幕方向、动作匹配（Match on Action）是否成立；道具状态 / 服装 / 光线在镜间是否一致
- **Gate 3 参考绑定齐备**：出现角色的镜头是否都挂了角色 ref；场景图 / 道具图是否齐；同一角色是否复用同一基准图
- **Gate 4 镜头语言有效性**：每个运动是否有动机；景别是否服务于信息；是否存在"为动而动"或堆镜头
- **Gate 5 版权与合规**：无克隆在世艺术家 / 品牌 / 版权角色；无真实人物与真实品牌露出；敏感内容按剧本红线处理

**评审结论**：PASS 交付 / REVISE 局部重画（指出哪一 gate 哪一镜）/ REJECT 重做。不虚构已修复。

## 常见踩坑对照表

| 踩坑 | 后果 | 对策 |
|---|---|---|
| OTS 反向对切 | 两人看向同一侧，不成对视 | 每场首格画轴线示意，全程同侧 |
| 忘挂参考图 | 角色脸漂移、场景变样 | 绑定检查：逐镜核对 ref 齐备 |
| 假设模型记得前镜 | 道具开合状态、服装在镜间跳变 | 连续性锚点写进**每条** prompt |
| 运动无动机 | 画面"能动就动"，观感廉价 | 每个运动必须写出它要完成什么 |
| 镜头堆积 | 1 分钟塞 30 镜，节奏碎 | 按 beat 定量，一个镜头一个变化 |
| 只写"电影感" | 提示词无信息量，出图随机 | 写景别 / 角度 / 运动 / 光线四件具体项 |
| 资产表膨胀 | 群演、陈设都单独建模 | 明确标注不单独建模项 |

## 与上下游的交接

- **上游**：剧本 skill 的 IP bible（人物名录、情绪曲线）+ 角色 / 场景 skill 的 bible 与基准图——全部经 `recall_memory` 与画布读工具取，不要求用户重述
- **下游**：drama-motion-video（镜头表 → motion 提示词 → 图生视频）、drama-audio-design（镜头表的 Audio 列 → TTS 与声音设计说明）、drama-qc-review（审片与派发修复）；本 skill 的镜头表（含 Beat / Blocking / 运动 / 连续性锚点）是这三者的共同输入契约
- 剧本改动后：资产表与受影响镜头需重跑；角色 / 场景基准图变更时，引用它的分镜 ref 需重新绑定

## 规则与边界

- 不虚构已出图；确认前不调用 `run_*`
- 芯片 key（@I1/I2）不是画布节点 id；禁止 `connect_nodes` 连芯片
- 已有资产不得重复生成；资产表标注"不单独建模"的项不得进建模流程
- **图生视频、motion prompt、动态分镜不在本 skill 范围**（见 drama-motion-video skill）
- 剧本台词不得改写；本 skill 只做镜头化呈现
