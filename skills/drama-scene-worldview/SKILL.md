# 短剧/漫剧场景与世界观设计

## 何时使用

用户要为短剧/漫剧设计世界观或具体场景，包括：

- 世界观设定（都市情感 / 古风宫廷 / 玄幻修仙 / 悬疑 / 末世等）
- 场景设定图、定场图（establishing shot）
- 同一场景多视角 / 多时段图（白天 / 夜晚 / 雨天）
- 室内景、街景、建筑外观、氛围图
- 泛化的"给这部剧设计世界 / 场景要有统一感"需求

**角色设定走 drama-character-design skill；剧本走 drama-script-writing；分镜（含场景在镜头中的呈现）走 drama-storyboard skill；视频脚本不在本 skill 范围**。

## 世界观参数（写任何场景 prompt 前先定）

借鉴 a5c-ai/world-building 的 world parameters。短剧/漫剧按需裁剪，一次性问全或从用户给出的剧本文本/简介提取：

- **时代**：什么年代？（现代都市 / 古代王朝 / 近未来 / 架空）
- **地理与文化**：哪里？什么社会风貌？（影响建筑、服饰、道具风格）
- **科技/超自然规则**：什么可能、什么不可能？（玄幻修仙须显式定义法术视觉形态）
- **视觉基调**：写实 / 风格化程度（与角色 skill 的画风选项保持同一套）

世界观参数一经确立即写入项目风格圣经（`save_memory` 登记），后续所有场景 prompt 遵守；用户 waived 或已提供剧本文本则不再追问。

### 世界观分层（macro → micro）

- **Macro（一段话即可）**：地理格局、时代氛围、权力结构、视觉基调——保证"世界感"统一
- **Micro（落到具体场景）**：每个要出图的场景建一份"场景档案"

## 场景档案（Location Profile）—— 每个关键场景必建

借鉴 a5c-ai/world-building 的 Location Profile Template，适配短剧节奏做精简：

```
## [场景名]（如：女主的旧公寓）
- 基本信息：内/外景、剧情功能（这里发生什么）、出场集数/场次
- 物理描述：规模、建筑风格、布局、关键特征（窗口朝向、楼梯位置、
  出入口——多视角图时布局不能自相矛盾）
- 氛围：光线（主光源方向/时段/色温）、色调（词+hex）、材质质感、情绪
- AI Image Prompt：由以上字段生成的定场图 prompt
```

- **关键固定结构（must not change）**：布局与关键特征相对位置、主光源方向、材质与色调基调——多视角 / 多时段图在这些项上只允许按剧情声明的差异变化（如"夜晚版"只改光线与时段，不改布局）
- 场景类型要点：内景重"生活痕迹"（lived-in feel）、公共空间重人流与时段、自然景重天气与尺度

## 世界观色板与角色配色区分

借鉴 a5c-ai/world-building 的 world color strategy：

- **主色**（占画面主导）/ **辅色** / **点缀色** / **禁用色**（避免出现的颜色）
- **角色配色编码**：主角 / 反派 / 配角各自的代表色，写进色板——角色出镜场景图中，角色服装色与场景主色形成既定关系（呼应或对比），防"同一角色在不同场景换衣服颜色"
- 色板用词 + hex，与角色 bible 的色板表共用一套格式

## 视觉风格指南（项目级，一次建立全程复用）

- **建筑参照**：年代与地域参照（"90 年代中国南方小城""唐风木构"）
- **材质与质感**：表面质感词（粗糙 / 做旧 / 抛光）、新旧程度（崭新 / 生活痕迹 / 破败）
- **色彩温度**：暖 / 冷倾向、饱和度水平、对比度策略（如悬疑剧低饱和高对比）
- **风格参照**：参考剧集 / 画师 / 摄影风格（用户给出则登记，不给则按类型给默认）

## 执行步骤

1. **定世界观参数**：ask_user 一次性问全（时代 / 视觉基调 / 超自然规则），或从用户提供的剧本文本提取后向用户确认
2. **建项目风格圣经**：视觉风格指南 + 世界观色板（含角色配色），`save_memory` 登记；已登记则 `recall_memory` 读取直接复用
3. **建场景档案**：对每个要出图的场景填 Location Profile；场景多时按剧情重要性排序，一次批量建档案再逐个出图
4. **建节点 + 写 prompt**：`upsert_media_node` 创建 image 节点；每条 prompt 顶部带 fidelity lock 段落（保持参考图场景身份不变：布局、建筑结构、关键特征相对位置、材质、色调基调；不得重新设计场景；不得增删结构），正文按"场景主体 → 氛围/光线 → 风格关键词 → 质量词"展开
5. **挂参考图（数据层）**：侧栏参考图用 `apply_sidebar_attachments`（mode=localRefs）；画布已有图才用 `attach_refs`；ref 顺序先该场景定场图（若有），后风格参照图
6. **连视觉边（视觉层）**：每个场景的**定场图作基准图**，同场景其他视角 / 时段 / 机位图有向边指回定场图；场景间不互连（各自独立基准）
7. **自动分层**：`arrange_nodes(along_edges)` 按场景分组展开
8. **提议生成**：`propose_generation` 提议生成，等待用户确认；确认前不调用 `run_*`
9. **出图后 QA 闸门 + 定位**：先 `focus_node` 定位到新节点，再对照 QA 闸门自检并报告 PASS/REVISE/REJECT
10. **登记场景档案**：QA 通过后 `save_memory` 存场景档案（定场图基准节点 id + 档案全文），供后续分镜/出图会话复用

## 出图后 QA 闸门

- **Gate 1 世界观一致性**：是否符合世界观参数与风格圣经（建筑年代、科技/超自然视觉规则）；违规即 REVISE
- **Gate 2 场景身份一致性**：同场景多图之间布局 / 关键特征位置 / 主光源方向 / 材质是否与定场图一致
- **Gate 3 无虚构**：不得虚构设定外的建筑结构、招牌文字、认证标识；招牌/文字须用户确认过才允许出现
- **Gate 4 套图一致性**：所有场景同一视觉世界（画风 / 色温 / 饱和度 / 光照逻辑统一）；角色配色编码未被破坏

**评审结论**：PASS 交付 / REVISE 局部重画（指出哪一 gate 哪一项）/ REJECT 整体重做。REVISE/REJECT 时不虚构已修复，回到 step 4 重新写 prompt。

## 与剧本、角色 skill 的配合

- **上游是 drama-script-writing**：剧本 IP bible（世界观要点 / 场景出场标注：内·外景与时段）经 `recall_memory` 取用——场景档案的物理描述与氛围字段从剧本的出场标注起步
- 角色出镜的场景图：prompt 携带角色**锚点原文**（`recall_memory` 从角色 bible 取）+ `attach_refs` 挂角色基准图；场景 fidelity lock 与角色 fidelity lock 同时置于 prompt 顶部
- 画风以项目风格圣经为准（先建立者有效，后建立者跟随）；各 skill 登记的 bible 通过 `recall_memory` 互查

## 规则与边界

- 不虚构已出图；确认前不调用 `run_*`
- 芯片 key（@I1/I2）不是画布节点 id；禁止 `connect_nodes` 连芯片
- **场景档案不可省略**（单张氛围图可精简为一段档案，但不跳过）；布局类字段无依据时先问，不脑补
- 按用户意图动态选型：用户没要的类型（俯瞰图 / 番外 Q 版世界观）不要自作主张加入
- 每个场景可给 1–3 个定场图变体标推荐项
- **分镜、剧本、视频脚本、图生视频不在本 skill 范围**（剧本见 drama-script-writing、分镜见 drama-storyboard）

## 提示词写法

- **fidelity lock 段落**（每条 prompt 顶部必带）→ 场景主体 → 氛围 / 光线 → 风格关键词 → 质量词；光线信息显式写时段与主光源方向（"黄昏、暖橙侧光 #e8a25c，光源来自画面左侧窗"）——多图一致性靠"同一份光照描述逐字复用"
- 情绪落到画面语义（"压抑"写成"低饱和冷色调、狭小构图、头顶单一冷白光源"），不堆形容词
- 色彩用词 + hex；显式声明不得出现的元素（无水印、无设定外文字、无虚构品牌）
