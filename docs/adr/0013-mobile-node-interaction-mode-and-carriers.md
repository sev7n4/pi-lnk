## 0. 术语与本 ADR 的范围

| 口头名词 | 本 ADR 含义 |
|---|---|
| **模式①** | **agent 驱动画布** —— 用户在对话页写原始创作意图，agent 推理并调用工具驱动画布创建 / 生成。**移动端主战场** |
| **模式②** | **用户主动与画布协同** —— 用户在画布页点 ＋FAB+ 手工建节点、填提示词、生成。**能力主要在 PC** |
| **五态** | D-C 状态机：empty / generating / pending / confirmed / error（交互门控唯一真相源） |
| **选择模式** | 多选（开 / 关），叠加在五态之上的第三维度 |
| **锚** | 对话 ⇄ 画布的连接器。**两枚品牌资产**：`anchor-locate.png`（定位/引用锚，功能性）/ `anchor-generate.png`（创作锚，「点击锚→创作」，见 `docs/design/2026-10-24-brand-anchor-icon-spec.md` §4） |

**范围**：移动端画布单节点（文本 / 图片 / 视频 / 音频）从创建到删除的全业务。与 PC 的差异只做「对齐盘点」，不改 PC 行为。

**不在本 ADR 范围**：PC 端交互（PC 已有 `DockStudioRouter` 全量参数 + 元素编辑 / 局部重绘）；移动端模式② 的全量参数（明确不做）。

## 背景

2026-10-24 真机走查三条反馈，经代码级审计确认全部属实，且比表面更深：

| # | 反馈 | 代码级根因 |
|---|---|---|
| ① | 创建节点为什么单击就默认打开 studio dock | #578 修掉「新建后自动弹编辑器」后**残留同源另一入口**：`resolveMobileNodeTapIntent` 对无产物节点返回 `editor`（空节点 tap 进编辑 sheet），#578 还给空瓦片加了「点按生成 / 点按撰写」CTA，把违背制度化 |
| ② | 节点管理操作应走长按 | 长按已是唯一管理入口，但**操作集不全**（缺保存到本地 / 存入资产库 / 副本含上游）且**不认状态**（生成中可删可编） |
| ③ | 文本/图片/视频/音频查看后关不回去、没有 X | 查看器唯一退出是左上角一枚 `‹`（U+2039 细笔画、透明底、无标签）——**不是被遮挡**（viewer z-90 > 顶栏 z-85；壳层挂画布容器外，无 fixed 包含块陷阱），是**识别失败**；且无背 scrim、无下滑手势、音频在查看器是死分支 |

更深一层的冲突：现行实现与 R1 自己上线的引导语「**点按播放 · 长按编辑**」自相矛盾——tap 策略把「空节点 → 编辑器」写成了默认路径。

此后连续四轮评审又暴露了三个结构性问题（本 ADR 的真正起因）：

1. **移动端节点交互实为两种模式**（① agent 驱动 / ② 用户主动 FAB+），而规格把它们当**一套**写 ⇒ 载体选择无法自洽。
2. **模式① 下移动端编辑 = PC studio dock 全量参数**（`MobileNodeEditorSheet.vue:2,77-87` 直接 import 并挂载 `DockStudioRouter`，dock-studio 6 panel + 12 shared ≈ 4800 行）⇒ 与 agent 驱动心智冲突：参数在 propose 时已由服务端写死（`proposeGeneration` 写 `imageModel`/`imageAspect`/`imageResolution`/`videoSettings`），用户再调 ⇒ **两套参数语义打架**。
3. **「局部反馈给 agent」缺载体** ⇒ 用户只能"整段改词重生成"，无法"圈出这一块说哪里不对"。

## 考虑过的方案

### 方案一 · 载体分工（查看 / 编辑 / 生成各选一种）

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| **A · 三载体按模式分工**（本 ADR 选定） | 每种模式心智自洽；模式① 轻、模式② 全；与既有 ADR-0011（节点即确认面）兼容 | 移动端要维护两套编辑载体 | **选定** |
| B · 一套载体通吃（保留 PC dock） | 实现最省；两端完全一致 | 模式① 下参数双语义 + 4800 行在窄屏（#578 走查⑥ 已实证参数选择器**根本弹不开**） | 与 agent 驱动心智冲突 |
| C · 移动端只做查看，编辑全回 PC | 移动端最轻 | 模式① 的核心闭环（看→标注→回对话→再生成）在移动端断了 | 断掉主战场闭环 |

### 方案二 · 迭代粒度（局部 vs 整体）

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| **A · 局部 + 整体并存**（本 ADR 选定） | 覆盖"整体换词"与"这块不对"两类真实意图 | 需一条标注通道 | **选定** |
| B · 只做整体改词 | 最省 | 用户无法指出具体位置 ⇒ 反复来回 | 体验退化成"描述不清楚就重抽" |
| C · 只做局部标注 | 表达力最强 | 用户想整体改方向时无从下手 | 缺"换方向"的能力 |

### 方案三 · 标注层形态

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| **A · 手指自由圈选 + 一张带标记的整图 + 一句话**（本 ADR 选定） | 零新契约、零服务端改动；移动端手势一套覆盖四类；用户"划得歪"也没关系 | 精度不如精确蒙版（"改图"类需求不够用 ⇒ 留 PC） | **选定** |
| B · 精确裁切区域图 + 结构化坐标契约 | 精度高；可支持程序化局部重绘 | 需新增片段契约 + 服务端解析 + 渲染回执；移动端要重做框选/套索/拖段/选段四套手势且要求"画得准" | 复杂度放错一侧 |
| C · 复用 PC `annotateModel` 全套工具 | 复用现成 | 多工具栏违背"不要太多选择工具"；且那套语义是"改产物"（马赛克/水印/签名），不是"反馈 agent" | 语义不同源 |

> ⭐ **方案三 A 的核心判据**：**agent 的输入是「图 + 话」，不是「图 + 坐标」**——坐标是给程序看的，人话是给 agent 的。把"精确圈定"交给 agent 的识图能力，是把复杂度放在对的一侧。

### 方案四 · 生成归属（模式①）

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| **A · 生成权归 agent**（本 ADR 选定） | 与 propose 协议一致；单一执行路径；用户意见天然在对话上下文里 | 用户不能在画布页直接改参数重跑 | **选定** |
| B · 移动端保留「生成」钮直接提交 | 用户自主性强 | 绕过 propose 确认（服务端有硬守卫：客户端无权把 `pending_confirm` 翻成终态）；产生双执行路径（agent 重生成 vs 用户手动生成）；用户此刻在画布页，其意见只有回对话页才对 agent 有效 | 状态归属混乱 |
| C · 双轨（pending 前归 agent、confirmed 后归用户） | 灵活 | 状态归属仍混；两套心智并存 | 复杂度无收益 |

### 方案五 · 锚的回传形态

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| **A · 锚作标注浮层主按钮「⚓ 带回对话」**（本 ADR 选定） | 一步完成；锚在产出物诞生地；复用 `anchor-locate.png`（品牌守卫已锁"不新造图标"） | 标注浮层多一枚按钮 | **选定** |
| B · 查看器右上角独立锚按钮 | 位置显眼 | 右上已有 X·改词·⋯ ⇒ 违反 §11.3 克制原则；且多一步（先出浮层再点图标） | 拥挤 + 绕路 |
| C · 标注完自动回传 | 零操作 | 违背品牌叙事；用户失去"发不发"的控制权；违背 ADR-0011 的"单一可操作确认面"精神 | 剥夺控制权 |

## 决定

### 决定一 · 四条交互铁律（P1–P6）

- **P1 单击 = 查看。** 任何类型、任何状态，单击都不进入编辑。空 / 生成中 / error（无旧产物）= 无 op + 轻提示；**pending / confirmed = 查看**。
- **P2 长按 = 管理。** 节点自身的管理操作（编辑 / 重命名 / 引用 / 副本 / 多选 / 删除 / 资产库 / 保存本地）只从长按动作 sheet 进，唯一入口。
- **P3 全屏层必须可退。** 查看器与编辑 sheet 都必须同时具备「右上角 X」与「下滑关闭」两条通道；退出即停（停播 / 停朗读），进行中的生成提示不丢。
- **P4 载体服从模式。** 见决定二。
- **P5 标注只有一支笔。** 见决定四。
- **P6 传送一律经锚。** 对话 ⇄ 画布之间的任何内容搬运（取节点 / 送标注图 / 送资产 / 批量引用）都必须经由锚（`anchor-locate.png`）——**同一枚 glyph，不因载荷不同而新造图标**；且必须"看得见落地"（切页 + 芯片 + toast 至少其一），失败必须明说降级。

### 决定二 · 模式① / 模式② 分工与三载体形态（**I1 / J1 / K1**）

| | **模式① agent 驱动（主战场）** | **模式② 用户主动 FAB+（次要，主要在 PC）** |
|---|---|---|
| **查看载体** | **类型原生查看器**（图片灯箱可缩放 / 视频播放器可逐帧 / 文本阅读器 / 音频**不进查看器**、磁贴内联波形） | 同左 |
| **编辑载体** | **轻量「提示词 + 意见」编辑器**：提示词（可改词）+ 我的意见（自由文本）+ 参数**只读摘要一行** + 引用 chips + 提交按钮「**发给 agent 修改**」。**无参数控件、无生成钮** | **最小参数编辑器**：类型 + 提示词 + 模型/比例（后置到 M3）。**明确不做 PC 全量参数** |
| **生成归属** | **agent**。移动端**不出现「生成」钮** | 用户自己（画布页提交） |
| **画布页角色** | **观察 + 表态**（看产物、标注、提意见） | **创作**（建节点、写提示词、提交生成） |

- **I1** 查看 = 类型原生查看器 + 内置标注层。（否决：I2 统一文本节点式 ⇒ 产物降级；I3 复用 PC `MediaPreviewOverlay` ⇒ PC 浮层与移动端全屏层不同构）
- **J1** 编辑 = 轻量「提示词 + 意见」编辑器、参数只读。（否决：J2 现状复用全量 dock ⇒ 参数双语义 + 4800 行窄屏不可用；J3 收进二级页 ⇒ 复杂度高收益低）
- **K1** 生成权归 agent。（否决：K2 移动端保留「生成」钮 ⇒ 绕过 propose 确认 + 双执行路径；K3 双轨 ⇒ 状态归属仍混）

⭐ **不接 PC studio dock 的根因**（不是"移动端屏幕小"这一条）：**模式① 的参数所有权在 agent 侧**（`proposeGeneration` 已写死），用户再调 = 两套参数语义打架；且模式① 的心智是"我说，你做"。

### 决定三 · 迭代闭环：局部 + 整体并存（**F1**）

- **整体粒度** = 改词（已覆盖，§16.3.1 / §12.3 改词铅笔）。
- **局部粒度** = 在查看器内圈选 + 附意见 → 作为引用块进 composer → 在对话里提意见 → agent 重生成（§13 / §16.3.1）。
- **F1** 局部迭代协作与引用 / 操作集同批 M2 实现。（否决：F2 推 M3 ⇒ 主闭环延后一轮；F3 仅记录 ⇒ 等于不做）

### 决定四 · 标注层 = 手指自由圈选 + 一张带标记的整图 + 一句话（**L1**）

- **唯一工具 = 手指自由圈选**（canvas 画笔）。产出「**带标记的整图 PNG**」+ 一句文字意见。
- ⛔ **取消**：「标注片段」结构化契约 / 区域**裁切**截图 / 框选·套索·拖段·选段四套手势 / 多工具栏。
- ✅ **保留整图**：裁切丢上下文（agent 不知"这是整图哪里"）；整图带标记保留全部语境。
- ✅ **四类节点收敛为「一张图 + 一句话」两种形态**（**只有底图不同，工具与契约完全一致**）：

| 类型 | 底图 | 标注动作 | 引用去向 |
|---|---|---|---|
| 图片 | 当前图 | 手指自由圈 | composer 引用芯片（image + 文字） |
| 视频 | **暂停后的当前帧** | 手指自由圈 | composer 引用芯片（image + 文字） |
| 音频 | **波形图**（`useNodeWaveform` 真实 peaks） | 手指在波形上划 | composer 引用芯片（image + 文字） |
| 文本 | 该段文字 | ——（文本本身即引用内容） | composer 引用芯片（text） |

- ⭐ **零新数据契约、零服务端改动**：复用 `SidebarAttachment` 现有字段——图走 `url`、意见走 `text`、归属走 `sourceNodeId`、类型 `mediaType:'image'`。

### 决定五 · 锚 = 统一载荷信封，标注回传经锚（**M1**）

- **锚的产品定义 = 双向连接器**：对话→画布 = 「取」；画布→对话 = 「传」。
- ⭐ **核心结论「锚 = 统一载荷信封」**：节点引用 / 标注图 / 资产库 / 多选批量**四类载荷共用 `SidebarAttachment`** ⇒ **新增载荷不需要新增图标**。
- **M1** 标注回传的锚 = **标注浮层的主按钮「⚓ 带回对话」**（用 `anchor-locate.png`）。（否决：M2 查看器右上独立锚 ⇒ 违反克制原则 + 多一步；M3 自动回传 ⇒ 违背品牌叙事 + 剥夺控制权）
- **形态判据**：锚 = 「产出物诞生地」的传送动作 ⇒ 圈完 → 浮层（意见输入 + ⚓ 带回对话）→ 合成上传 → **切回对话页** → composer 出现芯片 → 用户补一句 → 发送。
- ⭐ **移动端特殊职责**：PC 是左右同屏，移动端是**页签切换** ⇒「带回对话」= 切回 chat 页签 + 载荷已入 composer，用户落地即见芯片。
- **可见性铁律**：上传中态（契约拒 blob URL ⇒ 必须先上传）/ 切页 + 芯片 / 失败明说降级（视频跨域无 CORS ⇒「本条只带文字，未附截图」）。

### 决定六 · 其余拍板项

| 项 | **决定（已拍板）** | 理由摘要 |
|---|---|---|
| **A** 操作集范围 | **A4** 全补 + 删除走「**撤销优先**」（见决定八） | D5/D6 是既有承诺（PC 有、移动端缺），补齐无争议；A2 会让缺口继续累积。删除的确认方式由决定八统一为"撤销优先"（iOS 判据 + 仓库既有 `useCanvasUndoStack` 支撑） |
| **B** 生成中能否删除 | **B1** 禁止 | 生成中删除 = 中断一个已消耗积分的任务；B2 的二次确认文案反而在教用户"可以中断" |
| **C** 新建后引导 | **C2** 仅空瓦片 CTA（最小） | 模式① 下空节点由 agent 创建，模式② 才需引导；C1 toast 是额外噪音。C2 = 唯一入口已在瓦片上 |
| **D** 音频查看器分支 | **D1** 删 `type` 中的 audio | 音频永不进查看器（磁贴内联），留死分支 = 未来有人按契约调它必得空白屏 |
| **E** 操作入口形态 | **E1** 仅长按唤起菜单 | P2 单入口铁律；#578 已因双入口付出过代价（双卡片框）。E2 待真机发现性不足再议 |
| **G** 磁贴提示词常驻显示 | **G1** 无产物态为主内容、有产物态降级为可点「提示词」chips | 提示词是"产物的来由"，应全周期可回看，但不与产物争主位 |
| **H** 多选选择模式视觉 | **H1** 进入模式后全局节点浮现圆形指示器 + 轻点切换 | 对标 iOS 照片多选；现状"每加一个节点都要回画布找→长按→弹 sheet→点多选"是坏交互 |

### 决定八 · 跨端视觉与组件哲学（**N1**）—— iOS HIG / Material 3 对齐

> 起因：评审追问「图标、组件、交互是否充分借鉴 iOS 的极简与品牌高端哲学（Android 下也用）」。逐条比对 Apple HIG 现行原文与 Material 3 规范后，发现**三处组件选型错误 + 四处规范盲区**，本决定给出修正。

**三条修正（逐条附 HIG 原文依据）**：

| # | 现状（错误） | HIG / MD3 判据 | 修正 |
|---|---|---|---|
| 1 | 长按 → 底部 Action Sheet 承载全部管理操作 | HIG：*"Use an action sheet — **not a menu** — … people expect a **menu** to appear when they **choose to reveal it**"* | **改用 Menu 语义**（长按唤起菜单；Action Sheet 仅留给破坏性确认） |
| 2 | 一级平铺 11 项（M2 目标）/ 现有 7 项 | HIG：*"**Avoid displaying more than four buttons** in an action sheet, including the Cancel"*；MD3 `R5.7` limit icons to 2-3 | **一级 ≤4–5 项 + 二级「更多」**；⛔ 禁可滚动 Action Sheet |
| 3 | 删除确认弹层内「删除」置底 | HIG 现行：*"place [destructive] buttons at the **top** of the action sheet"*（iOS 8 旧做法才是置底） | **确认弹层内破坏性置顶 + 红色**（Menu 内仍置底 + 分隔线） |

**四类盲区的修正**：

| # | 盲区 | 修正 |
|---|---|---|
| 4 | **图标体系无纪律**（查看器用 `‹` 文本字符当图标） | 零图标库**保持不变**（品牌优势）；新增图标一律**内联 SVG**（照抄 `MobileSheet` 既有正确范式：24 网格 + `stroke-width:2`）；⛔ 禁文本字符当功能图标；**锚是唯一例外**（品牌位图资产，守卫已锁） |
| 5 | **「改词」放右上角违反可达性** | iOS 原则"高频操作放下方拇指区、顶部只放低频" ⇒ **「改词」下沉到查看器底部主栏**；右上 = **X · ⋯** 两枚 |
| 6 | **两套浮层皮肤并存**（`MobileNodeActionSheet` 是裸 `position:fixed` div，无 scrim / 无把手 / 无圆角 / 无 Teleport ⇒ 点浮层外画布不会关） | **移动端浮层一律走 `MobileSheet` 基座**；禁止新写第二套皮肤 |
| 7 | **删除用"二次确认"而非"撤销"** | HIG：*"**Undo beats 'Are you sure?'** for reversible actions"*；仓库**已有** `useCanvasUndoStack` 且明确支持 delete→undo 恢复 url/status ⇒ **删除 + Snackbar「撤销」**；仅**不可撤销**的删除（级联删上游 / 跨项目）才走确认弹层 |

**同时确立的三条品牌哲学**（作为跨端组件的判据框架）：**Deference 谦逊**（UI 服务内容，不与内容争）／**Clarity 清晰**（一屏一主动作，图标 ≤3）／**Depth 层次**（用层与材质表达层级，不用边框）。

**文案规范**：操作项统一**动词短语**（对齐既有 `MobileMultiSelectMoreSheet` 的「生成 / 停止 / 重新生成 / 分组 / 导出」）；破坏性确认标题必须**说明后果**。

### 决定七 · 落地分期

- **M1 原则闭环（P0）**：D1 tap 门控落状态、D2 查看器 X + 下滑关闭 + 退出停播、D3 多选态 tap 门控、空瓦片 CTA 文案改「长按编辑 / 撰写」。
- **M2 操作集 + 载体 + 迭代（P1）**：D5 删除（改「撤销优先」，见决定八）、D6 三项新增操作（进二级「更多」）、D7 长按状态门控、§12 pending 查看 + 改词（**下沉底部主栏**）、§13/§16.3.1 局部迭代（手指圈选 + 带标记整图）、§14 磁贴提示词分级、§15 多选选择模式、**D8 编辑载体改造（轻量编辑器 + 参数只读 + 发给 agent）**、**§18 锚语汇（⚓ 带回对话）**、**决定八 跨端组件哲学（Menu 化 + 数量上限 + 破坏性位置 + 图标体系统一 + 浮层收敛 `MobileSheet`）**。
- **M3 固化**：行为级守卫（tap 门控 / 查看器退出 / 多选门控 / 删除撤销 / 标注回传接线 / **Menu 化与数量上限 / 破坏性位置 / 无文本字符图标 / 浮层基座**）、按 §4.1 / §5 矩阵逐格勾选的真机走查清单、规格随实现升版。

## 后果

**正面**：
- 移动端模式① 的闭环第一次自洽：**看产物 → 圈一下 → 写一句 → ⚓ 带回对话 → agent 重生成**，全程在对话页收口，与 ADR-0011「节点即确认面、单一可操作面」同构。
- 移动端不再背 4800 行 PC 参数面板；参数所有权归 agent 一处，消灭双语义。
- 品牌叙事「对话-锚-画布」在产品里第一次有统一载体：**锚 = 双向连接器 = 统一载荷信封**。
- 局部迭代能力让"对产物提意见"从"描述不清楚就重抽"变成"指着说"。

**负面 / 代价** ❗：
1. **移动端失去"自己改参数重跑"的能力**（模式①）——用户想改比例/模型/时长，只能回对话页用自然语言说。**这是有意的取舍**（参数是 agent 的实现细节），但对"参数敏感型用户"是真实的能力回退。模式② 保留最小参数集作为补偿。
2. **标注精度不如精确蒙版**——"我要精确替换这一小块"做不到 ⇒ 这类需求留 PC。移动端标注是**意图表达**，不是**像素编辑**。
3. **合成图必须先上传**（引用契约拒 blob URL）⇒ 多一次网络往返 + 引用芯片需"上传中"态；弱网下用户会看到"发不出去"。
4. **视频跨域无 CORS 头时无法取帧** ⇒ 降级为"暂停 + 文字意见，不带图"。**这意味着视频的局部反馈能力弱于图片**（图片走 `/api/media/proxy` 同源化后可取帧）。
5. **模式① 撰写发生在对话页** ⇒ "我只想快速改个词不惊动 agent"在移动端无独立路径（改词仍要经轻量编辑器 + 发给 agent）——换来的好处是单一执行路径。
6. 🔴 **改契约后预期他人 mock 会撞**——§16 的"参数只读 / 无生成钮"会打破现有 `MobileNodeEditorSheet` 的测试断言（`DockStudioRouter` 的 `generate` emit 透传、R4-T2 断链修复用例），合并 master 后需同步他人 mock。
7. **两套编辑载体并存**（模式① 轻量 / 模式② 最小参数）⇒ 移动端要维护两套；缓解：模式② 的参数集可后续向模式① 靠拢，反之不可（受 propose 协议约束）。
8. 🔴 **低频操作被下沉二级 ⇒ 多一次点击**（决定八）——「存入资产库 / 保存到本地 / 副本含上游」三项从一级 Menu 移到二级「更多」；换来的是一级 ≤4–5 项的可扫读性（HIG 硬约束）。**这是有意取舍**：iOS 的菜单设计本就以"短而可扫读"为第一原则。
9. 🔴 **删除改「撤销优先」⇒ 误删不再有确认拦截**（决定八）——完全依赖 Snackbar 的可见时长与撤销按钮；缓解：时长 ≥5s + 单一「撤销」action（MD3 `R5.16`）；**不可撤销的删除**（级联删上游 / 跨项目）仍走确认弹层。
10. **Menu 化的改动面被低估**（决定八）——长按浮层从 Action Sheet 改 Menu 牵动组件语义、二级下钻、破坏性位置、文案、图标；现有 `MobileNodeActionSheet` 的 6 个既有测试全部要改。缓解：**与 Task 4 合并为一个 PR**，既有测试逐条重写而非删除。

**将来要注意**：
- 若真机走查显示长按 discoverability 不足，**E** 可升级为 E2（长按 + 卡片右上「⋯」双入口，同源同容器）——但不得回到"卡片铺胶囊"。
- 若 agent 侧出现"看不懂用户圈的位置"的反馈（可观测：agent 反问"你指哪"），说明**整图 + 标记**不够用，需评估**区域裁切 + 坐标**（决定三方案二）——**但那时应新增一条 ADR，而不是悄悄改**。
- 若跨设备多模态模型策略变化（`supportsVisionModel` 判定），音频/视频的降级边界需重估。
- 若模式② 在移动端的真实使用量超过预期，需评估是否把参数集补全（但**不可**把全量 dock 搬进移动端）。
- 若真机走查发现「更多」二级下钻的点击成本过高（用户找不到低频操作），可**提升一两个最高频的低频项**回一级（仍守 ≤5 项上限），**不可**直接恢复"11 项平铺"。
- 若删除的 Snackbar 撤销在真机上被大量忽略（误删反馈变多），再评估是否对**特定删除类型**（如批量删除）加确认弹层——**不整体回退**。
- 存量浮层（`MobileMultiSelectMoreSheet` / `ProfilePane` 等）的硬编码圆角与动效令牌化属**既有债**，本期不清理（另开 ADR）。
