# ADR-0004: 视觉能力用三态函数声明，禁止正则猜测

| 字段 | 值 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-10-03（PR #124） |
| 决策者 | 项目发起人 |

## 背景

pi-runtime 需要知道"这个渠道/model 支不支持视觉输入"，以决定图片是正常处理
还是降级成占位符。

原先的做法是**拿模型名跑正则**猜：
```
/gpt-4o|claude-3|gemini/ 之类
```
问题（#123、#124、#127、#129 四条PR 都在修这条链路）：

- **静默降级**：不支持视觉的渠道传了图片，图片被悄悄替换成占位符文字，
  **用户和调用方都看不出来**，还以为是模型返回的
- **正则漏**：新模型名匹配不到 → 误判不支持
- **正则误伤**：名字里碰巧含关键词的模型被误判支持
- **BYOK 渠道没法表达**：用户自带的渠道能力各异，正则无从判断

## 考虑过的方案

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| 模型名正则 | 简单 | 漏+ 误伤 + 静默降级 | ❌ |
| **显式三态函数**（选中） | 准确、可测、覆盖 BYOK | 每个渠道要声明一次 | ✅ |
| 运行时探测（发真请求试） | 最准 | 慢、费token、无法覆盖未配置渠道 | ❌ |

## 决定

1. **视觉输入能力独立成三态函数**，不再靠正则：
   - `true` 明确支持
   - `false` 明确不支持
   - `undefined` **未知/未声明** → 按不支持处理但**不静默**（要报错或告警）
2. **Nest→pi-runtime 必须透传该声明**：视觉能力要一路传到 pi-runtime。
   ⚠️ 这一跳缺失时，前面的修复全部不生效（#127 的标题就是这个意思：
   "缺了它 #123/#124 不生效"）—— 说明**声明链路必须端到端打通**，不能只改一端。
3. **BYOK 渠道可自行声明**（#123）：根治"用户自带渠道传图被静默降级"。
4. **llm-override 的 parse 层也要透传**（#129）："识图链路最后一跳"。

## 后果

**正面**
- 能力判断准确，不靠猜
- 新模型/新渠道有明确的登记动作，不会漏
- 静默降级变成显式失败

**负面 / 代价** ❗
- 新增渠道必须声明能力，否则走"未知"分支
- **三态里"未知"最容易被实现成"当作false"** —— 那就退回了静默降级，
  必须让"未知"在日志/响应里可见

**将来要注意**
- 改这条链路时，**端到端验证**（Nest 声明 → 传输 → pi-runtime 消费），
  只改一端等于没改
- 新增 provider 渠道时，把它的视觉能力登记进三态函数
