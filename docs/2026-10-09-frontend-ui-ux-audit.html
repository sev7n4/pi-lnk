五个必须先解决的致命问题

P0 主题是"路由导航的副作用"，浅色模式在 16/17 条路由上根本不存在

useCanvasTheme.ts 在模块加载时把主题写到 <html>，而全仓只有 CanvasPage.vue 导入了它。其余 16 条路由是懒加载，模块永不求值 ⇒ data-canvas-theme 属性从未被设置 ⇒ 一律回落到 :root（深色）基线。更糟的是：一旦进过画布页，该属性会残留在 <html> 上不再移除，导致后续页面的外观取决于"用户是否访问过画布并按过切换"——完全不可预测。同时 0 处 prefers-color-scheme，默认硬编码 dark。

P0 三个颜色真相源并行，Tailwind 侧的调色板是"深色专用"死值

neowow-tokens.css（74 个 --neo-*）与 tailwind.config.js（brand/electric/warm/surface）各写一套同义色，且 Tailwind 侧没有浅色变体。讽刺的是 Tailwind 里定义的 brand.* 使用次数为 0，而组件里硬编码了 ~20 处 Tailwind 默认靛蓝 #6366f1 / #818cf8——与品牌紫 #6d5dfc 不是同一个颜色。加上 index.html 的 bg-[#141414]（utility 层，优先级压过 base 层的 token），同一个"页面底色"语义存在 5 个不同值。

P0 令牌文字色在两个主题下都不满足 WCAG AA（已实测复算）

用 WCAG 相对亮度公式 + alpha 合成独立复算：--neo-text-muted 深色 3.60:1、浅色 2.60:1，均低于 AA 要求的 4.5:1。浅色主题的两个语义色作为文字使用时同样不合格（error 3.45:1 / warn 2.93:1）。另有 67 处 text-white/30|35|40 低透明度文字（2.69–3.83:1），且大量用在 10–11px 字号上，连"大文本豁免"都不适用。

P0 画布在触屏上完全不可用：平移绑定鼠标中/右键，连线手柄 hover 才出现

:pan-on-drag="[1, 2]" 是 d3-zoom 的中键 + 右键，无触屏等价物 ⇒ 单指平移不可能。节点连线手柄 .handle-plus 默认 opacity:0; pointer-events:none，仅由 @mouseenter 触发显示 ⇒ 节点连线——节点图的核心交互——在触屏上死掉。下载/保存按钮同样 display:none 直到 hover，且无 :focus-within 回退。全仓 @touchstart 命中 0。

02八大维度诊断

2.1 色彩系统 48/100

三段式问题：定义层不完整（语义色只有浅色版、18 个 token 深色独占）、消费层大面积绕过（629 处硬编码）、机制层断裂（主题属性只在一条路由上被写）。另外 13 个被引用但从未定义的 token（--neo-success / --neo-danger / --neo-panel / --neo-surface / --neo-fg …）会让整条 Tailwind 任意值声明在计算值阶段失效——静默降级成"没有边框、没有底色"，且不报任何错。这类 bug 正是本项目最难查的那一类。

AgentSideRail.vue:3034 'border-[var(--neo-danger)]/40 bg-[var(--neo-danger)]/10' ← --neo-danger 未定义 → 整条声明失效 AgentSideRail.vue:3037 'border-[var(--neo-success)]/40 …' ← 同上 CSS 注释自己也承认了这个坑（neowow-tokens.css:48-50）： "缺定义会让 color-mix(var(--neo-text)…) 整条声明失效 → 背景透明不可见"

2.2 排版系统 55/100

没有字号阶梯。字重、行高、字族靠 text-xs/sm/base 零散取用，text-[10px] / text-[11px] / text-[12.5px] 这类非标值大量出现（仅 text-[10px] 就有 20+ 处），且常与 30–40% 透明度叠加——既不可读也不统一。字体栈声明了 Inter / Unbounded 但 Google Fonts 是阻塞加载，fallback 只有 system-ui，切换时会 CLS。

2.3 视觉层次 62/100

毛玻璃层级（chrome / popover / glass-lite / dock）的设计意图是清晰的，这是加分项。但层级被 z-index 混乱稀释：19 个魔法值里 z-[9000]（CanvasPage:4617）、z-[1000]、z-[999] 并存，而 dock 只用 z-[46]——意味着一次新增浮层就可能盖住整个工具轨。间距上 1,084 处裸 px、最常见的非网格值是 10px(272) / 11px(165) / 6px(117)，没有 4/8 网格约束，区块节奏靠手感。

2.4 响应式布局 38/100

182 个组件里只有 20 个用了任何断点前缀，2xl: 为 0，CSS 里零个宽度媒体查询。移动端感知只有一个 useAgentMobileLayout.ts（767px，max-width 桌面优先，与 Tailwind 的 min-width 策略相反），且只被 AgentSideRail 消费。硬性溢出点已定位：UsageDayTable 表格 min-w-[640px]、CanvasTaskHistoryPanel w-[404px]、三处 w-[340px] 固定宽浮层。

2.5 交互体验 58/100

反馈状态覆盖不均：56 个按钮会在异步期间 disable（好），但大多只变 opacity 不出 spinner；19 处 animate-pulse 骨架屏全是手写、尺寸参差；24 个空状态用了 4 种不同透明度（text-white/30|40|50 + opacity-60）。"同一个交互、多种视觉结果"的典型：.is-on 激活态有 ≥4 种实现（main.css:250 用 hi-bg、三个 overlay 用 color-mix、两个用 accent-text、RefineToolRail 用 rgba(0,89,179,.16)）。Tooltip 全用原生 title=（274 处）：键盘不可达、触屏不可达、~1s 延迟、无法定制样式。

2.6 动效过渡 52/100

时长与缓动无 token（13 种时长 / 130 次 0.15s ease），且 ease 是浏览器默认曲线而非设计曲线。prefers-reduced-motion 只覆盖 8 处，16 个无限动画无降级——包括 8s 的 logo 常驻旋转和 4 条常驻连线流动动画，WCAG 2.2.2（Level A）要求 >5s 的并行动画可暂停，目前没有暂停控件。另有 8 处对 width/height/left 做过渡（触发 layout reflow）。

2.7 无障碍 34/100 — 最低分维度

结构性缺陷，不是细节问题：

  • 焦点不可见：8 处 outline:none 无替代，含 Agent 主输入框（.agent-prompt-field 同时 border:none+background:transparent，聚焦后完全看不出）。全仓无全局 :focus-visible 基线。
  • 无焦点陷阱/归还：8 个 role="dialog" 全是 div，0 个 <dialog>、0 个 focusTrap。6 个还标了 aria-modal="true"——告诉辅助技术"外界是惰性的"，但实际 Tab 能跑进背景画布，比不标更糟。
  • Esc 缺失：5 个 dialog 和 10+ 浮层无 Esc 关闭，含 ForceChoiceDialog（强制选择弹窗，aria-modal 且无退出键）。
  • 语义缺失：CanvasPage 5,094 行里 <header>/<nav>/<main>/<h1-h6> 命中 0；StudioShell.vue:34 在 App.vue:21 的 <main> 内嵌了第二个 <main>（无效 HTML）；无跳转链接；导航激活态无 aria-current。
  • 异步静默：aria-busy 全仓 0，aria-live 仅 2；204 处 ElMessage 在无 role 的游离容器里，出错对读屏用户不可见。

2.8 性能 44/100

三个可量化的主要开销：

  • INP：每节点 .neo-gen-card { backdrop-filter: blur(10px) }（7 个节点组件使用）⇒ 画布上有 N 个媒体节点就有 N+10 个合成模糊层，每层都要独立的合成 + 回读。这是画布页最大的单点开销。
  • INP：134 个无 key 的 v-for（77 个遍历可变集合），Vue 退化为按下标 patch ⇒ 每次插入/重排整棵子树重渲染，流式 Agent 消息会反复重挂载。
  • LCP：main.ts:3-5 全量引入 ElementPlus + 349 KB 阻塞 CSS，而绝大多数调用方只需要 ElMessage；public/auth/ 五个登录视频共 15.1 MB 且两个 <video> 同时 preload="auto"；favicon 是 522 KB PNG（而 258 字节的 SVG 闲置未用）。

03Design Token 体系定义（核心交付）

这一节是可直接复制落地的新令牌体系。设计原则：三层架构 + 单一真相源 + 语义命名 + 主题只切换第二层。迁移后，组件里不应再出现任何 hex / rgba 字面量，也不应再出现任何 Tailwind 颜色工具类。

3.1 架构：三层令牌

层前缀职责主题相关举例
L1 原始层
Primitive		--lnk-{色相}-{档位}纯色板，不含语义。全主题共享，永不切换。否--lnk-purple-500
--lnk-neutral-950
L2 语义层
Semantic		--lnk-{类别}-{角色}绑定用途。唯一切换层：[data-theme='light'] 覆写这一层。是--lnk-text-muted
--lnk-surface-2
L3 组件层
Component		--lnk-{组件}-{部位}组件私有契约，默认引用 L2。允许被 props 覆写。间接--lnk-btn-primary-bg
--lnk-node-card-bg

关键决策：为什么必须三层而不是现在的一层？ 现在的 --neo-* 把 L1 和 L2 混在一起（--neo-bg 既是"中性色 950"又是"页面底色"），导致浅色主题必须逐个覆写 60 个变量、漏掉 18 个也没人发现（这正是"18 个 token 深色独占"的根因）。改成三层后，浅色主题只需覆写 L2 的 ~28 个语义变量，L1 色板两主题共用 —— 漏覆写在数学上变得不可能。

3.8 落地机制与守卫

  1. Tailwind 接入：把 L2 语义变量映射进 tailwind.config.js 的 colors（用 rgb(var(--x)) 或 var() 形式），使 text-primary / bg-surface-base / border-subtle 成为合法工具类；同时删除 brand/electric/warm/surface 这套死配置（11 项里 10 项零使用）。加 darkMode: ['class', '[data-theme="dark"]']，杜绝 dark: 走 prefers-color-scheme 的三方错配。
  2. CSS 变量完整性守卫（扩展现有 palette-parity.test.ts 的思路）：新增测试断言「L2 深色块与浅色块的变量名集合完全相等」——这一条能一次性消灭"18 个深色独占 / 4 个浅色独占"整类问题。
  3. 引用完整性守卫：扫描全部 var(--lnk-*) 引用，断言每个都在 L1/L2/L3 中有定义。这一条能消灭"13 个未定义 token 导致整条声明静默失效"这类最难查的 bug。
  4. 对比度守卫：对 L2 文字/语义色跑 WCAG 计算，<4.5:1 直接 fail。把本报告实测的公式固化进测试，杜绝再次引入 --neo-text-muted 这种值。
  5. 硬编码颜色门禁：新增 lint 规则禁止新增 hex / rgba( / text-white / bg-[#，存量 629 处进 allowlist 逐批消化（每批 PR 必须减少计数）。
  6. Element Plus 主题对齐：把 main.ts 的全量引入改为按需引入（顺带省掉 349KB 阻塞 CSS），并通过覆写 --el-* 变量指向 --lnk-*，让 76 个 EP 组件实例与 204 处 ElMessage 融入品牌语言，而不是现在"默认主题 + 7 行局部覆写"的割裂状态。
