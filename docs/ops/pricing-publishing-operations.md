# 定价发布流与白名单灰度 · 运营操作指导

> 适用版本：master `d82451c5`（P1-a，2026-10-15 上线）。
> 对应规格：`docs/superpowers/specs/2026-10-13-pricing-baseline-config-design.md` §8.4（发布流）/ §8.5（白名单灰度）。

## 0. 前置条件

| 项 | 说明 |
|---|---|
| 入口 | `http://<服务器>:8888/admin`（ops-console）→ 左侧菜单 **「价目发布流」「灰度发布」** |
| 鉴权 | 首次进入弹出 token 输入框，填 `LNKPI_ADMIN_TOKEN`（在 CVM `/opt/lnkpi/.env` 中配置）。缺失/错误时所有操作返回 401 |
| 审计 | 所有写操作自动落 `adminAuditLog`（action：`pricing-version.publish` / `pricing-gray.create` / `pricing-gray.promote` 等），可在「审计日志」页回查 |

**名词**：
- **版本**（PriceListVersion）：一套完整价目表，状态 `draft`（草案）→ `active`（生效）→ `archived`（被替代/回滚）。全网同时只有一个 active。
- **条目**：`matchKey`（如 `video:minimax-h3:768p:5s:base`）× `capability` × `credits`（积分价）。
- **灰度 release**：白名单灰度发布，状态 `active`（生效中）→ `promoted`（已转正）/ `rolled_back`（已关停）/ `expired`（窗口过期）。

**当前生产状态**（2026-10-15）：active 版本 = `v1-legacy-equivalent`（与旧常量逐字等价的基准价）；v2 拉新期草案尚未导入（见 §2 步骤 1）。

## 1. 场景 A：日常小幅调价（不走灰度）

1. 「价目发布流」页 → **复制 active 建草案**：填版本名（如 `v2-hotfix-1`，必填）+ 备注 → 自动打开草案。
2. **行内改 `credits`**：只能正整数（非法值前端拦截，不会发请求）→ 保存（返回写入条数）。
3. **影响面预览**：核对
   - `changed`（本次改价条数）/ `unchanged` / `added`
   - `maxIncrease` / `maxDecrease`（最大涨/降幅，发布确认弹窗会再次展示最大涨幅）
   - **地板违规**（标红）：某条 `credits < 成本 × 1.05` —— **有标红则发布必被 400 拒绝**，先改价
   - **无成本覆盖 N 条**（黄色标注）：这些条目没有成本数据，未做地板校验（见 §4）
4. **发布** → 二次确认 → active 切换、旧版本 archived、审计落账。
   - 计价侧有 30s 缓存：最长约 30 秒全网生效（发布成功的提示会如实说明）。
5. 发错了 → **回滚**（回到上一个 active 版本，同样有审计 + 30s 缓存）。

## 2. 场景 B：v2 拉新期价目发布（推荐走灰度）

### 步骤 1：导入 v2 草案种子（CVM 上一次性，幂等）

```bash
ssh root@119.29.173.89
docker exec lnkpi-api sh -c "cd /app/apps/server && node_modules/.bin/tsx prisma/seed-pricing-v2-draft.ts"
```

- 产出：`draft` 版本 **`v2-launch`**（共 318 条：改价 188 条 = 图片全档 12 + minimax-h3 768p/2k 全档；其余 130 条逐字复制 v1）。
- 幂等：同名 draft 重跑会整体重新 upsert，计数不变。
- 防护：同名**非 draft** 版本已存在 → 400 拒绝；已有其它 active 版本时重新播种 v1 → 拒绝（单 active 保护）。

### 步骤 2：建灰度 release（「灰度发布」页）

1. 名单框粘贴手机号：**换行 / 逗号 / 分号 / 空格**分隔均可；系统按 `User.phone` **原样精确匹配**（不做 +86 / 横线归一化——号码库里存什么就填什么）。
2. 点 **预览命中**：面板显示「命中 N 人 / 未命中 M 个」，未命中号码逐个列出（改名单或改版本后预览态立即失效，需重新预览——这是防错设计）。
3. **0 命中时创建按钮禁用**（后端也会 400 拒绝，错误信息含全部未命中号码）。
4. 选 draft 版本（`v2-launch`）→ 可选窗口（默认 `now ~ now+7 天`）→ 创建。
   - 同一时刻**只允许一个生效中的灰度**，已有则 409（先关停/转正旧的）。
   - 生效后名单用户立即按灰度价计价；灰度版本缺行时自动回落全局价并在服务端 warn。
   - 灰度期间名单用户的每笔扣费流水带 `grayReleaseId`，报告可精确归因。

### 步骤 3：观察（报告抽屉）

- 交易笔数（**含退款**）/ 退款笔数 / 按用户消费分布 / 分目录金额。
- ⚠️ 口径：「分目录金额」**包含 refund 行金额**，不是净扣费；净消费看「按用户消费」列。
- 窗口过期后，列表刷新时自动把 release 置为 `expired`。

### 步骤 4a：达标 → **转正（promote）**

- 对灰度版本执行正式发布（走同一套发布事务：地板校验 + 旧 active 归档 + 审计），release 置 `promoted`。
- 前提：release 是 `active` 且灰度版本仍为 `draft`。

### 步骤 4b：发现问题 → **关停（rollback）**

- release 置 `rolled_back`，名单用户**约 30 秒内**回到全局价（计价缓存）；灰度版本本身不动。
- 若是**版本**发错了（非灰度问题）→ 去「价目发布流」页做版本**回滚**。

## 3. 报告口径与注意事项

| 项 | 说明 |
|---|---|
| **4s 档「无成本覆盖」30 条** | CostRate 表没有 4 秒档成本行（5s 锚点对 4s 是假地板），这 30 条未做地板校验、在 diff 中显式列出。审批时人工把关；P2 补录 4s 成本行后自动恢复校验 |
| **价格地板** | 任何条目 `credits < ceil(成本 × 1.05)` → 发布 400（事务原子：失败零写入）。这是防亏损硬规则，不是 bug |
| **30s 缓存** | 发布 / 回滚 / 关停后，计价侧最长 30 秒内仍按旧价。界面文案已如实标注；紧急场景可 `docker restart lnkpi-api` 立即生效 |
| **quote 永不失败** | 计价任何异常（含灰度数据故障）自动落全局价兜底，用户侧不会因灰度故障报错；服务端留 warn 日志 |
| **新环境部署** | 不再 boot 自播种。无 active 版本时启动即降级常量兜底（日志有 error），发布后**运行时自愈**；或先跑 `docker exec lnkpi-api sh -c "cd /app/apps/server && node_modules/.bin/tsx prisma/seed-pricing.ts"` |

## 4. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 所有操作 401 | token 缺失/错误 | 重新粘贴 `LNKPI_ADMIN_TOKEN` |
| 发布 400「地板违规」 | 某条 credits 低于成本 ×1.05 | 提价，或先核实该条 CostRate 数据是否正确 |
| 创建灰度 400「未命中」 | 名单 0 命中（错误信息含全部未命中号码） | 核对号码与 `User.phone` 完全一致（含国际区号格式） |
| 创建灰度 409 | 已有生效中的灰度 | 先关停或转正现有灰度 |
| 改完名单创建按钮仍禁用 | 预览态已随名单变更失效（防错设计） | 重新点「预览命中」 |
| 发布成功但价格没变 | 30s 计价缓存 | 等待或重启容器 |
| 想撤销一次 promote | promote = 正式发布 | 走「价目发布流」页的版本回滚 |
