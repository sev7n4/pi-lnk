# 移动端画布页真机走查验收清单（2026-10-20）

> 配套设计文档：`2026-10-19-mobile-canvas-ux-redesign.md`（§8 为原始 T/I/V 表）。

> 基线：线上 = `origin/master` `0fada1ab`（PR #509 / #511 / #514 均已上线）。

## 使用规则

1. **设备**：iOS Safari + Android Chrome **各跑一轮**（标记 ★ 的手势项是源码推断修复，两端结论可能不同，必须分别记录）。
2. **截图命名**：`场景编号-设备-序号.jpg`，如 `J3-C1-ios-1.jpg`。每个场景按「需截图」列出数量。
3. **判定**：结果列填 `通过` / `不通过` / `存疑`；不通过时在备注写现象。
4. **尺寸量法**：44px 热区按 **CSS px** 量（截图像素 ÷ 屏幕 dpr；量不准就圈出来我来复核）。
5. **前置数据**：建议先造一个含 3~4 个节点的会话（文本节点 → 图像节点 ×2，其中两个建为分组），并留一个**空画布**会话跑 J1。

## 溯源对照（与设计文档 §8 / 已修缺陷）

- T-x = 触控手势项，I-x = 入口 IA 项，V-x = 视觉项（编号同设计文档，便于回查）。
- `#509` = 底部锚定改 fixed（＋FAB / 保存状态行 / 多选动作条）；`#511` = 提议确认钮 44px + 待确认期进度卡让位；`#514` = 根容器 100dvh（胶囊滚出 + 空态偏低根治）。三项均为**真机复验**重点。

## 第二轮（2026-10-21 02:00 走查）已修项 —— 需复验

本轮 4 条反馈全部落在一类缺陷上：**jsdom 无视口 ⇒ CI 全绿也看不见**。修复已上线，复验点如下（复验前先清缓存强刷）。

| # | 原反馈 | 修复 | 复验怎么看 |
|---|---|---|---|
| R-1 | 长按 A →「多选」→ 再长按 B：**A 被取消**，只剩 B | `enterMultiSelectMode` 在多选态改为 toggle（加入/移出），sheet 文案随态变「加入多选 / 移出多选」 | 长按 A→多选→长按 B ⇒ 动作条「已选 2」；再长按 A ⇒ 回到「已选 1」 |
| R-2 | ＋FAB 被对话裸条盖掉一半（只剩紫色月牙） | 裸条左移 56px 让开 ＋FAB，两者并排；FAB 落位只锚页签栏（不再依赖运行时测量变量） | 画布页左下：＋FAB 完整可见，裸条在它右侧，**不重叠**；画布页只有**一个 ＋**（裸条内的 ＋ 在空闲态已隐藏） |
| R-3 | 从 ＋sheet 创建节点后 studio dock 自动弹出 | 移动端 dock **默认折叠**（把手 tap 才展开）；创建节点不再自动弹 | 创建文本/图片/视频/音频节点 ⇒ 面板不弹；点底部把手才展开 |
| R-4 | dock 面板底行被挤压、发送钮被裁一半；面板顶得太高 | 模型选择器可收缩、动作组不收缩；移动端输入区收到 56/132 | 展开 dock：发送钮完整可点，模型名截断但右侧不溢出；面板不再顶到接近屏顶 |
| R-5 | 「按住说话」不可用且零反馈 | 能力探测：不支持时文案降级为「点按输入」；识别失败按错误码给可见提示 | 不支持的机型：条上写「点按输入」，长按不再有幻觉承诺；权限被拒会弹明确提示 |
| R-6 | 空态文案「按住底部条说话」 | 改为「点 ＋ 新建节点，或点底部条输入」 | 空画布文案已更新 |

> 另：多选入口共 3 个（长按 sheet「多选」/ 进入多选态后**直接点按**其它节点累加 / PC 的 Shift 与框选）。移动端没有框选（单指拖 = 平移，属手势分工的既定裁决），所以移动端的主路径是**进入多选态后直接点按**。
