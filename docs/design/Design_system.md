## 1. 设计方向选型

品牌关键词：**lnk π**（π 无限不循环 / 链接）、**超创**、**墨鱼 π**（墨 / 深海 / 触手连接）、**电光紫**（创造力·AI）、**电流青**（连线电流·能量流动）、**琥珀橙**（积分·能量值·氛围光）。

### 方向 A｜星尘 Stardust — 延续并强化现有深色毛玻璃

- **手法**：保留电光紫主导 + 毛玻璃层级，加深中性阶、补对比度、加间距/字号/层级令牌。
- **优势**：改动最小，约 70% 硬编码可原地替换；视觉延续性强。
- **劣势**：**不解决根因**。诊断里"浅色模式在 16/17 路由不存在"是结构缺陷，A 只是把深色做得更精致，浅色依旧是二等公民。且"紫色毛玻璃"是 2023–2024 年 AI 产品的通用皮肤，承载不了「墨鱼 π / π」的品牌独特性。
- **代价**：低（1–2 周），天花板低。

### 方向 B｜墨流 Ink Flow — 中性承载结构，品牌色只做点睛 ⭐ **推荐**

- **手法**：
  1. **墨阶承担 90% 结构** — 表面层级、文字、边框全部走中性，靠**明度差 + 排版**建立层次，而不是靠颜色。
  2. **电光紫收缩为 10% 点睛** — 只用于主 CTA、激活态、选中环、品牌标识。
  3. **电流青 / 琥珀橙各锁一个语义** — 青＝能量流动与连线，橙＝积分与消耗；两者**禁止挪作他用**。
  4. **双态对等** — 画布默认深色沉浸（图像/视频工作需要），周边页默认浅色高效（列表/表单/阅读）。
- **为什么是它**：直接命中诊断三大缺陷——
  - 对比度失败的根因是"用 rgba 白透明度当文字色"，墨阶是实色，天然达标（§2.3）；
  - 629 处硬编码的根因是"没有中性阶可依赖"，有完整墨阶后组件不必自己造灰；
  - 视觉层次弱的根因是"靠多给一点紫"，改由排版阶梯 + 表面明度承担。
- **代价**：工作量最大（≈3–4 周），需团队对齐"再定调"。
- **⚠️ 关键澄清**：B **不是换 Logo、不是换主色**。品牌紫保留为点睛色，现有渐变资产 `#6d5dfc → #8a5cf6 → #b45cf0` 不动。它改变的是**系统重心**：从"紫色毛玻璃"移到"中性墨阶"。

### 方向 C｜双源 Dual-Source — 光暗严格对等，机制优先

- **手法**：不做视觉再定调，先把主题提升为应用级关注点，两主题严格成对 + CI 守卫。
- **优势**：直接修 P0。
- **劣势**：**只解决机制不解决审美**；且没有中性阶时，成对覆写的工作量反而更大。
- **代价**：中（1–2 周）。

### 结论

**选 B。** 理由有二：

1. A 的天花板是"更好的 2023 AI 皮肤"，C 只是 B 的子集。
2. **C 的机制整改（主题全局化 + 成对守卫）本来就包含在 B 的落地路径里**——选 B 不会丢掉 C 的收益，反之则丢掉审美。

## 1.5 品牌 IP：墨鱼锚 Inkfish Anchor（原创 IP 释义 × 调性传递）

> **一句话**：π 无限不循环，墨鱼把无限游成海；腕足提锚，锚灯亮处，想象落定成图。
> 本章是「方向 B 墨流」的 IP 层注解——§2 的每一个令牌都应能在这张表里找到自己的出处。

### 1.5.1 「lnk π 超创」三段解

| 字段 | 释义 | 设计转译 |
|---|---|---|
| **lnk** | link，链接。墨鱼的十条腕足就是「lnk」的具象——同时向十个方向连接 | 每一条边框、连线、引用关系都是一次 lnk；描边体系（border/edge）是「连接」的语法 |
| **π** | 无限不循环：永远除不尽、每一位都不重复。**理性（数学常数）与浪漫（永不重复）共存于同一符号**——这正是「超越理性」的创造力的图腾 | display 字体只用于拉丁/数字/**π 符号**（§2.4）；加载 shimmer 相位逐帧偏移、永不重样（§2.9），「无限不循环」是动画参数不是口号 |
| **超创** | 超越性创造：不是把已有的事做好，而是产出尚不存在的东西 | 产品里唯一「无中生有」的时刻 = 生成。电光紫（创造力·AI）只服务这个时刻 |

### 1.5.2 墨鱼 π：五个可译的生物特征

IP 形象的原型是墨鱼（cuttlefish）。选它不是因为可爱，是因为它的每个特征都能**一对一翻译成设计机制**——IP 不是贴图，是系统的比喻：

| # | 生物特征 | 释义 | 落进设计的哪里 |
|---|---|---|---|
| 1 | **墨**（喷墨 / 拟态重写环境） | 墨是介质，「墨即画」——把空白重写成图，正是生成的形状 | 墨阶 `ink-0..1050` 承担 90% 结构；深色画布 = 沉浸深海 |
| 2 | **色素细胞**（每平方厘米百万级，瞬间换肤） | 同一只鱼，一秒一种皮肤 = **风格的无限显色** | 电光紫 ≤10% 点睛，只给「显色时刻」：生成、选中、品牌标识 |
| 3 | **喷射推进**（头足类最快的运动方式） | 极速 = 生成速度的体感 | 动效 `fast 150ms` + `accelerate` 出场；生成中的推进感 |
| 4 | **腕足并行**（8 腕 + 2 触腕） | 并行连接、多任务、多模态 | 画布节点连线、多任务并行的视觉语法 |
| 5 | **深海 + 拟态** | 沉浸与自适应：随环境变色而本体不变 | 双主题对等（§1 方向 B 第 4 条）：深色 = 深海沉浸，浅色 = 日光海面，**结构（墨阶）不随主题漂移** |

### 1.5.3 锚：三层寓意（IP 核心意象）

墨鱼腕足所提之锚，是这套 IP 的原创核心。它回答的问题是：**一个关于「无限」的品牌，为什么需要一个「定」的符号？**

1. **创造的定锚（发散 → 收敛）**。π 无限不循环，想象发散无边界；但「生成」这个动作的形状恰恰是：把无限可能锚定成一张确定的图。腕足向外张开（发散），锚向下一沉（落定）——**锚就是生成按钮**。
2. **信任的锚点（不确定中的确定）**。深海无光，AI 生成的不确定性（漂移、幻觉、失控）需要可信赖的锚。产品承诺：提示词定了就不漂移、风格可复现、消耗透明。UI 层面，锚的稳定性由**墨阶**兑现——90% 的结构不动如锚，界面越稳定，点睛色越可信。
3. **锚链 = 层级（elevation）**。锚链一节一节垂入深海，每一节都比上一节更深更沉。表面层级 `surface-canvas → sunken → base → raised` 就是锚链的四节，阴影五档 `shadow-xs..xl` 是放链的刻度——**抬升一级 = 放出一节锚链**（已在 §2.8 落地为变量，守卫锁「深色必须比浅色重」「档位单调加重」）。

### 1.5.4 锚灯：深海里的确定性信标

**航海实义**：锚灯（anchor light）是船停泊时点亮的全方位信号灯，向四周宣告「我已定泊，此处稳定」。嫁接到深海语境：无光深海里唯一的定点光。

⇒ **设计转译：电流青 = 锚灯**。它只作为**点状确定性信号**出现：

- 焦点环（把你的注意力锚定在这）；
- 成功态（已定泊）；
- 进行中/连线（能量在流动的位置）。

**硬规则：锚灯禁止大面积铺底。** 灯一旦变成海面，就失去信标的意义——这正是「青 = 唯一语义：能量流动/连线」的 IP 表述（§1 品牌关键词第 5 条）。

### 1.5.5 调性传递映射表（IP 元素 → 令牌/机制）

| IP 元素 | 寓意 | 承载令牌/机制 | 守卫 |
|---|---|---|---|
| 墨 | 创造介质 | 墨阶 `--lnk-ink-*` + 表面四层 | 棘轮 8 类只减 |
| 触手 | 连接 | 描边体系 `border-*` / `edge-*` | 成对性 |
| 色素细胞显色 | 风格切换的瞬间 | `--lnk-accent*`（≤10%）+ 品牌渐变（F-5 已锁） | 品牌锚点 describe |
| 锚链 | 层级深度 | `--lnk-shadow-xs..xl` + `shadow-lnk-*` 工具类 | 深色>浅色 / 单调加重 |
| 锚灯 | 确定性信标 | `--lnk-energy`（青）用于 focus/成功/进行中 | 单语义守卫 |
| π | 无限不循环 | display 字体 + shimmer 相位偏移动画 | reduced-motion 强制静止 |
| 喷射推进 | 极速 | `duration-fast` + `ease-accelerate` | 时长阶梯守卫 |
| 拟态/深海 | 双主题自适应 | `data-theme` 全局机制（P0 已上线） | 机制不变量 4 条 |

### 1.5.6 IP 应用硬规则

1. **墨鱼形象只出现在情感位**：空态、生成完成、错误安抚（如「墨鱼帮你看着呢」类微文案图标位）。**禁止进入关键操作路径**（按钮、表单、导航）——IP 是慰藉，不是路标。
2. **IP 插画与 UI 图标严格分区**：IP 插画允许填充和渐变；UI 图标一律 1.5px 线性（§2.11）。**IP 不下放为 icon**。
3. **π 符号只进 display 字体场景**（Logo、Hero、大数字），不进正文。
4. **文案不卖萌**（§4 语气已定）：IP 情感由形象与动效承载，文字保持专业克制——两条腿不能同时跳舞。
5. 品牌三锚点（紫/青/橙）语义互斥的规则不变（§2.2），本章只是给它们补上出处。

## 2. Design Tokens

### 2.1 架构：三层

| 层 | 前缀 | 职责 | 主题切换 | 举例 |
|---|---|---|---|---|
| **L1 原始层** | `--lnk-{色相}-{档位}` | 纯色板，按明度排序，不含语义 | 否，全主题共享 | `--lnk-ink-900`、`--lnk-purple-500` |
| **L2 语义层** | `--lnk-{类别}-{角色}` | 绑定用途 | **是，唯一切换层** | `--lnk-text-muted`、`--lnk-surface-base` |
| **L3 组件层** | `--lnk-{组件}-{部位}` | 组件私有契约，默认引用 L2 | 间接 | `--lnk-btn-primary-bg` |

**为什么必须三层**：现有 `--neo-*` 把 L1 和 L2 混在一起（`--neo-bg` 既是"中性 950"又是"页面底色"），导致浅色必须逐个覆写 60 个变量、漏了 18 个也没人发现。三层化后浅色**只覆写 L2**，L1 共用，漏覆写在数学上不可能。

**三条硬规则**：
1. 组件只允许消费 L2 / L3，**禁止直接引用 L1**。
2. 每个 L2 变量必须在深浅两块中**同名成对**。
3. **文字色一律实色 hex，禁止 rgba 透明度**——透明度文字的对比度随所在表面变化，单一令牌无法保证。

### 2.4 字体

```css
--lnk-font-sans:    'Inter', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', system-ui, sans-serif;
--lnk-font-display: 'Unbounded', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', system-ui, sans-serif;
--lnk-font-mono:    'JetBrains Mono', ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
```

**中文产品必须西文/中文分开声明**。现状 `tailwind.config.js` 只写 `['Unbounded', 'system-ui', 'sans-serif']` —— Unbounded **没有 CJK 字形**，所有中文标题会静默回退，等于品牌展示字体在中文场景从未生效。

- `display` 只用于**拉丁字符、数字、π 符号**（Logo、大数字、Hero）；
- **中文标题靠字重与字距区分，不靠字族**；
- 正文一律 `sans`。

### 2.5 字号阶梯（Major Third 1.25，基准 14px）

工具型密集界面用 14px 基准，不用 16px。

| Token | 字号 / 行高 | 行高比 | 字重 | 用途 |

## 3. 基础组件规范

**通用状态契约**（所有交互组件必须实现全部 6 态）：

| 状态 | 视觉 | 技术契约 |
|---|---|---|
| default | 表面 `surface-base` + 边框 `border-default` | — |
| hover | 叠加 `hover-overlay` | `@media (hover: hover)` 内生效 |
| active | 叠加 `pressed-overlay` + `scale(.98)` | `:active:not(:disabled)` |
| focus-visible | **2px `border-focus` 外环 + 2px offset** | `:focus-visible`，**禁止 `outline:none` 而无替代** |
| disabled | 显式 `text-disabled` + 弱化表面 | `disabled` 属性 + `cursor:not-allowed`；**不用 opacity** |
| loading | 保留标签 + spinner，禁用交互 | `aria-busy="true"` + `role="status"` |

> **为什么 disabled 不用 opacity**：`opacity:.5` 会把文字对比度一起打下去（现状 `main.css:44` 就因此让禁用按钮低于阈值）。要用**显式禁用色**。

### 3.1 按钮 Button

| 尺寸 | 高 | 内边距(x) | 字号 | 圆角 |
|---|---|---|---|---|
| `sm` | 32 | 12 | 13 `sm` | `md` 8 |
| `md`（默认） | 40 | 16 | 14 `base` | `md` 8 |
| `lg` | 48 | 24 | 16 `md` | `lg` 12 |

| 变体 | 背景 | 文字 | 边框 | 用途 |
|---|---|---|---|---|
| `primary` | `accent` | `text-on-accent` | 无 | **每屏最多 1 个**主操作 |
| `secondary` | `surface-base` | `text-primary` | `border-default` 1px | 次级操作 |
| `ghost` | 透明 | `text-secondary` | 透明 | 工具栏、低强调 |
| `danger` | `error` | `text-on-accent` | 无 | 破坏性操作，需二次确认 |
| `link` | 透明 | `accent-text` | 无 | 内联跳转 |

- **图标按钮**：正方形，桌面 ≥32、**移动端 ≥44**；必须 `aria-label`（现状 127 个按钮仅靠 `title`，触屏与部分 AT 读不到）。
- **内部间距**：图标与文字 `gap-inline` 8。
- **A11y**：必须是真 `<button>`；`loading` 时 `aria-busy`；禁用时用 `disabled` 属性而非仅 `aria-disabled`。
- **禁止**：现状 7 个组件各写一份"白底黑字主按钮"（padding 3 种、圆角 2 种、字号 2 种、字重 2 种），统一走 `primary`。

### 3.2 输入框 Input

- 高 `md` 40 / `sm` 32；内边距 x=12、y=8；圆角 `sm` 6；背景 **`surface-sunken`**（比容器暗一档，形成"凹陷"感）；边框 1px `border-default`。
- **结构**：Label（上，13px `text-secondary`，间距 4）→ 控件 → 帮助文本（下，12px `text-muted`，间距 4）→ 错误文本。
- **focus**：边框转 `border-focus` + 2px 外环（`box-shadow: 0 0 0 2px`）。
- **error**：边框转 `error`，错误文本 `role="alert"` 并通过 `aria-describedby` 关联到输入控件。
- **placeholder**：`text-muted`（最差 4.90:1，达标）。**placeholder 不能替代 label**。
- **必填**：标记 `*` + `aria-label` 补"必填"，**不能只靠颜色和星号**（颜色单一信号对色盲不可辨）。
- 现状 20 处手写 `<input type="range">` + 5 套各写各的 CSS → 收敛为 `<AppSlider>`。

### 3.3 卡片 Card

- 圆角 `lg` 12；背景 `surface-base`；边框 1px `border-subtle`；内边距 **≥16 (`pad-card`)**；阴影 `sm`。
- 结构：`header`（标题 16px `md`/600 + 可选操作区）→ `body` → `footer`（右对齐操作）。
- **可交互卡片**：hover 阴影升到 `md` + `translateY(-2px)`；**整卡是 `<button>` 或 `<a>`，不是 div + @click**（现状 6 处纯 div 可点击，键盘完全不可达）。
- 卡片间距 `gap-stack` 12，区块间距 ≥`pad-section` 32。

### 3.4 弹窗 Modal / Dialog

- 遮罩 `scrim`；对话框背景 `surface-raised`；圆角 `xl` 16；内边距 24；层级 `z-modal`。
- 宽度：`sm` 400 / `md` 480 / `lg` 640 / `xl` 800；`max-height: 80vh` + 内部滚动。
- **A11y 契约（强制）**：
  1. 用原生 `<dialog>`，或 `role="dialog"` + `aria-modal="true"` + **焦点陷阱** + **关闭后焦点归还触发元素**；
  2. **Esc 关闭**（现状 5 个 dialog 和 10+ 浮层缺失）；
  3. `aria-labelledby` 指向标题。
- 底部操作区右对齐，**主操作在最右**；危险操作放最左并加确认。
- ⚠️ 现状 8 个 dialog 全是 div、0 个焦点陷阱，其中 6 个还标了 `aria-modal="true"` —— 告诉 AT"外界是惰性的"但 Tab 实际能跑进背景画布，**比不标更糟**。

### 3.5 导航 Navigation

**顶部导航**：高 64px（`--lnk-header-height`），`sticky top-0`，层级 `z-chrome`，背景 `surface-overlay` + 模糊，底边框 1px `border-subtle`。内容区 `max-width: 1280` 居中，左右留白 16（`sm` 24）。

- **激活态**：`selected-overlay` 背景 + `text-primary` + **`aria-current="page"`**（现状 AppHeader 只用 `bg-white/10 text-white` 表达，无 ARIA）。

**移动端**：`md` 以下隐藏横向标签，改用底部标签栏（高 56 + `env(safe-area-inset-bottom)`）或抽屉。**不能只靠隐藏**——现状 `<nav class="hidden … md:flex">` 在移动端直接消失，无任何替代入口。

### 3.6 表格 Table

- 表头：12px `xs` / 600 / `text-secondary`，背景 `surface-sunken`，`sticky`，底边框 1px `border-default`。
- 单元格：内边距 y=12 / x=16；行分隔线 1px `border-subtle`；hover 叠加 `hover-overlay`。

|---|---|---|---|
| `sm` | 20 | 8 | 11（仅数字/英文） |
| `md` | 24 | 8 | 12 |

- 形态：**状态标签**用 `radius-full`（Pill），**属性标签**用 `radius-xs` 3。

### 3.8 提示 Tooltip

- 延迟：进 200ms / 出 100ms；背景 `surface-raised`；圆角 `sm`；内边距 8×12；字号 12；阴影 `md`；层级 `z-popover`。

### 3.9 补充：Spinner / EmptyState / Toast

诊断发现这三类各有 5 / 24 / 1 种手写实现，必须收敛：

- **Spinner**：统一一个组件，尺寸 14/20/28，颜色继承 `currentColor`，`aria-hidden="true"`，外层容器负责 `role="status"`。
- **EmptyState**：统一结构（图标 + 主文案 14px `text-primary` + 次文案 12px `text-muted` + 可选操作），**文案由调用方传入但句式统一**（见 §4）。
- **Toast**：层级 `z-toast`，容器 `role="status"` + `aria-live="polite"`（错误用 `assertive`），4–6s 自动消失，可手动关闭，**同屏最多 3 条**。现状 204 处 `ElMessage` 在无 role 的游离容器里，读屏用户完全收不到错误。

### F-1 🔴 阻断：**既有对比度守卫的亮度公式是错的**

**证据**：`apps/web/src/styles/palette-parity.test.ts:82`

```ts
return 0.2126 * ch[0]! + 0.7152 * ch[1]! + 0.2992 * ch[2]!
```

WCAG 2.1 sRGB 相对亮度的蓝通道系数是 **0.0722**，不是 0.2992（后者是 YCbCr / 模拟视频时代的系数）。

**实测偏差**（正确公式 vs 仓库公式）：

| 配色对 | 正确 | 仓库公式 | 偏差 |
|---|---|---|---|
| `#131318` / `#a89dff` | 7.88 | 11.46 | **+3.58** |
| `#131318` / `#f4f4f8` | 16.88 | 19.91 | **+3.03** |
| `#131318` / `#22d3ee` | 10.25 | 13.19 | +2.94 |
| `#eef0f5` / `#1d4ed8` | 5.88 | 3.61 | −2.27 |
| `#eef0f5` / `#b3261e` | 5.73 | 6.90 | +1.16 |

最大偏差 **3.58**，且**方向随含蓝量变化**（对含蓝高的色系统性偏高）。偏高的方向正是**假绿**：不达标的配色被判为达标。

**判定：阻断。** 这条测试目前是"锁对比度"的唯一机制，机制本身不可信 ⇒ 它给出的绿灯没有证据力。

**处置**：新守卫 `design-token.test.ts` 已内联正确实现并注释说明；修 `palette-parity.test.ts:82` 时需**同步复核其既有断言阈值**（改公式可能让原本假绿的断言转红，那是真信号，不是回归）。

### F-4 已知边界（诚实声明，不算不通过）

1. **本评审只覆盖规范自身的一致性，不能证明实现一致。** 组件尚未实现，"规范很美、实现很乱"的风险依然存在 —— 这需要 §6 的 CI 守卫 + 视觉回归兜底。
2. **半透明玻璃表面上的文字未纳入静态对比度验证**。`surface-overlay` 是 rgba，其等效背景取决于背后的画布内容，静态不可判。已写入约束：**玻璃表面必须保证 backdrop 合成后明度不低于 `surface-raised`**。
3. **深色 hover 变深的视觉接受度**需要在真机上确认（§2.3）。这是为满足对比度做的刻意取舍，有代价。

### F-5 🔶 待决（P0 实施中新发现）：品牌渐变承载白字不达标

品牌渐变 `#6d5dfc → #8a5cf6 → #b45cf0` 两个主题同值。实测它承载白字的能力**沿渐变衰减**：

| 色标 | 白字对比度 | AA 4.5 |
|---|---|---|
| 起点 `#6d5dfc` | **4.54** | ✅ |
| 中段 `#8a5cf6` | **4.25** | ❌ |
| 终点 `#b45cf0` | **3.67** | ❌ |

影响面：`.btn-primary`（`main.css`）把白字压在这条渐变上，按钮右半区间的文字低于 AA。
**这不是本轮引入的**，两个主题一直如此，只是此前没人测过渐变内部的对比度衰减。

为什么不在本轮改：渐变属于"品牌锚点，改动需走品牌评审"（§2.2）。两个候选方案各有代价：

- **A. 压暗渐变末端**（`#b45cf0 → #7c3fd6` 一类）：可达标，但动品牌资产，需评审。
- **B. 主按钮改用实色 `--lnk-accent`**：可达标且不动品牌，但主按钮失去渐变质感 —— 是视觉改版。

当前处置：`design-token.test.ts` 锁了三色标不许漂移，并断言「白字压末端 ≥3:1（大字 AA）」——
即**记录偏差、只锁不许更糟**，把 A/B 的取舍留给品牌决策。

## 6. 固化方案

### 6.1 落地顺序（P0）

1. **主题机制全局化**——`index.html` 内联引导脚本（含 `prefers-color-scheme` 兜底），把主题从"画布页模块副作用"提升为应用级关注点：

```html
<script>
(function(){
  var s = localStorage.getItem('lnk-theme');
  var t = (s === 'light' || s === 'dark') ? s
        : (matchMedia('(prefers-color-scheme: light)').matches ? 'light' : 'dark');
  document.documentElement.setAttribute('data-theme', t);
  document.documentElement.classList.toggle('dark', t === 'dark'); // Element Plus
})();
</script>
```

同时删除：`index.html:2` 的 `class="dark"`、`index.html:13` 的 `bg-[#141414] text-white`（utility 层压过 base 层 token）、`useCanvasTheme.ts` 的模块级副作用。

2. **替换 `neowow-tokens.css`** 为 `design-tokens.css`（约 60% 可 1:1 改名，其余因语义重构需手工映射，映射表见诊断报告 §3.7）。

   > ⚠️ 当前 `design-tokens.css` **尚未被 `main.css` import**，是有意为之：此刻 import 会多加载 12KB 零消费者 CSS。
   > 它由 `design-token.test.ts` 直接读文件守卫，**不会静默腐化**；真正的 import 在第 2 步随迁移一起做。
3. **清扫深色专用类**（240 处 `text-white`、77 处 `border-white/`、59 处 `bg-white/`、25 处 `bg-black`）。
4. ⚠️ **第 1 步与第 3 步必须同批发布**——主题一旦全局化，87 个含深色旁路的组件会**立刻**在浅色下暴露问题。单独上第 1 步等于把隐性 bug 变成显性事故。
5. **修 F-1**（`palette-parity.test.ts:82` 蓝通道系数）。

### 6.2 关于"是否写进 AGENTS.md"：**不建议写正文，建议在 AGENTS.md 留指针**

**理由**（依据本仓库自己已建立的约定）：

1. `AGENTS.md` 开篇即声明其定位是**入口规范**，只放"任何时候都要看得见"的内容（项目目标 / 角色边界 / 系统地图 / 影响面矩阵 / 完成定义），并要求"改动本文件时每条陈述都要回代码核实"。把 ~600 行 token 表塞进去会稀释入口规范的可读性。
2. 设计体系是**高频演进**资产（调色、加组件、改间距都会动）。放进 `AGENTS.md` 会让入口规范变成高改动文件，与"入口规范应当稳定"相冲突。
3. 仓库已有成功先例：`docs/agent/tool-capability-catalog.md` 的正文在 `docs/agent/`，`AGENTS.md` 只在「改工具分层」一节留指针；`palette-parity.test.ts` 用**测试**而不是文档自觉来锁一致性。设计体系应沿用同一模式。

**因此**：

- **正文**：`docs/design/Design_system.md`（本文件）—— 单一真相源
- **令牌**：`apps/web/src/styles/design-tokens.css` —— 可执行 SSOT
- **守卫**：`apps/web/src/styles/design-token.test.ts` —— CI 强制
- **指针**：`AGENTS.md` 的「规范体系结构」表新增一行（见 6.3）

这样既保证"后续开发能看见"，又不牺牲入口规范的稳定性，且**用测试而非自觉来保证遵循**。

### 7.3 为什么字号 / 圆角 / 阴影没接进 Tailwind

Tailwind 默认阶梯与令牌命名**不是一一对应**：

| 类名 | Tailwind 默认 | 令牌 | 若覆盖 |
|---|---|---|---|
| `text-sm` | 14px | 13px | 全站正文变小 |
| `text-base` | 16px | 14px | 全站基准变小 |
| `rounded-xl` | 12px | 16px | 全站圆角变大 |
| `shadow-lg` | 预设黑投影 | 令牌投影 | 全站阴影变化 |

这些是**视觉改版**，不是主题修复，无法靠"构建通过"验证。本轮只新增**不与默认键冲突**的语义别名
（`duration-fast` / `ease-standard` / `z-chrome` / `shadow-glow`），默认值一个没动。
