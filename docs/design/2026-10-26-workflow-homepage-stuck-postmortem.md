> 状态：**根因已闭合**；止血已上线（PR #594）；根治见规格 `docs/superpowers/specs/2026-10-26-shared-agent-subscription-design.md`

## 2. 取证链（每一步都可复现）

### 2.1 服务端全绿 ⇒ 不是服务端故障
- `GET /api/health` → 200
- `lnkpi-service-guard.log`：23:28–23:57 每分钟 `api:up(healthy) matting:up(healthy) segment:up(healthy)`
- nginx `error.log`：**空**；无 5xx
- nginx → API 的在飞连接：`Recv-Q/Send-Q` 全 0（**无挂起请求**）
- 容器日志：20:32 之后零输出、零错误

### 2.2 决定性判据：请求**根本没离开浏览器**
同一时间窗 nginx access.log：

```
/api/agent/canvas/list  →  一条都没有      ← 浏览器里的 4 条从未到达服务器
全站请求总数            →  1 条（00:43:43 GET /api/agent/runs/events 200）
```

⇒ 请求卡在**浏览器的连接队列**里，15s axios 超时先到 ⇒ 被取消 ⇒ 服务端毫无痕迹。

### 2.3 队列指纹（服务端侧可见）
`access.log-20261026`：**23:36:59 单秒完成 109 个请求，其中 29 个是 `GET /api/agent/runs/events`**（4 个 499=客户端主动断开）。HTTP/1.1 每源最多 6 条在线 ⇒ 29 条同时完成 = **排队后齐发**。

### 2.4 占用方：会话级常驻订阅
实测 `GET /api/agent/runs/events`：`: observer-ready` + `data: {"type":"heartbeat"}` 之后 **30 秒以上不关闭** ⇒ **每条订阅 = 一条持续占用的连接**。

## 3. 根因

```
#574（2026-10-24 03:49）会话级常驻订阅
   └─ 每标签页/每实例一条长连接，靠服务端心跳维持、永不放弃
Chrome 同源 HTTP/1.1 硬上限 = 6 条连接
   └─ 标签页一多 ⇒ 槽位占满 ⇒ 之后的普通请求（项目列表等）排队饿死
#591（2026-10-25 20:20，项目面板跨端复用 + 创建通道收敛）
   └─ 移动端也开始拉列表 ⇒ 移动端最先撞上
#593（2026-10-25 23:13 合并、已上线）
   └─ single-flight + 30s 新鲜期 + 失败不清空：解决「并发放大 + 失败清空」
      ⛔ **不解除排队** ⇒ 症状照旧
```

### 3.1 为什么连续三天没人定位
10-24→10-25 五轮修补（#581/#582/#583/#585/#587）**全部在降低踩中概率**（砍首屏请求数、删全局预热、后台释放订阅），**没有一个动到真根因**。
更关键：`useProjectWorkspace.ts` 把同一形态记成**弱网特例**——

> *2026-10-19 事故的形态是「弱网/代理路径下 body 永不落地 ⇒ axios promise 不 settle ⇒『项目加载中』转不完」*

今天证明它可以是**连接饥饿**（同型不同因）。⇒ **「body 永不落地」必须先排除「请求未发出」再归因弱网。**

### 3.2 两处**仓库自己写下的**同机制记录
- `apps/web/src/App.vue`（#585）：*"用户连点历史项目 1/2/3/4，每次都建一条 SSE 长连接，同域 HTTP/1.1 只有 6 个连接；旧 SSE 未释放时新 SSE 又建 ⇒ 连接被占满 ⇒ `threads`/`events` 排队 55 秒"*
- `apps/web/src/components/agent/tail-visibility.ts`（#587）：*"Chrome 对单个 host 只有 6 条 HTTP/1.1 连接，后台页一多…前台请求就全部排队饿死"*

⇒ 机制早已被观察到，但被当作「请求太多」处理，**没有人把它和「长连接不释放」连起来**。

## 4. 我走过的两条弯路（都撤回）

| 弯路 | 错在哪 | 处置 |
|---|---|---|
| 建议「生产 nginx 开 http2 治 6 连接上限」 | 站点是**明文 HTTP**，`listen ... http2` 只启用 **h2c**；**浏览器只在 TLS 上用 h2** | 已上生产又**完整回滚**（备份 `*.bak-h2-20261026-010126`）；分支已删。实证：`curl --http2-prior-knowledge`→HTTP/2（服务端生效），但浏览器拿不到 |
| 第一版修复"命中记忆就跳过 list 直接进" | 打破 `WorkflowPage.test.ts` 的 **6 条移动端入口契约**（"优先进最近有产物的项目"依赖 list 数据） | 被自己的测试抓住 ⇒ 收窄为「**仅 list 失败时**兜底」，且**只对手势路径**生效 |

## 5. 已落地的止血（PR #594）

`useEnterCreation.enterCreation()`：**list 失败时用「记忆的项目」兜底**（localStorage `lnkpi:lastProjectId:<uid>` ⇒ 零请求）⇒ 连接饥饿时点锚**仍能进画布**。

- 既有契约不动：择优仍先 list 再择优；移动端自动分发 list 失败仍不跳转且有可见反馈。
- 测试：三文件 **54 例全绿**；**变异检验**（实现改回原样）⇒ 新用例如期变红 ⇒ 真守卫。
- `vue-tsc -b`：本次改动零类型错误。

## 6. 根治（已出规格与计划，待实施）

`docs/superpowers/specs/2026-10-26-shared-agent-subscription-design.md`（0 错 0 警）+ `docs/superpowers/plans/2026-10-26-shared-agent-subscription.md`（7 task）。

**核心**：同会话跨标签页用 `BroadcastChannel` 选举 leader，**全局只保留 1 条**订阅连接 ⇒ 6 连接额度还给普通请求。

## 7. 仍然欠着的账（独立立项）

1. **HTTPS + HTTP/2**：唯一能让浏览器用上多路复用的路径（明文端口开 h2c 无效，已实测）。
2. **可观测**：nginx 访问日志**缺 `$request_time`** ⇒ 排队无法量化；前端「在飞请求数」埋点。
3. **上游通道**：apimart / fal / minimax / stepfun 自 2026-10-24 18:31 起持续探活超时（>21h），多模型能力实际不可用。
4. **主页精选封面**：外域视频全部 `ERR_BLOCKED_BY_ORB` / `ERR_ABORTED` ⇒ 社区精选封面挂。

## 8. 复现与验证

- **复现**：Chrome 打开同一会话的多个标签页 ⇒ 槽位占满 ⇒ 品牌页点锚卡 15s。
- **验证（止血上线后）**：见 PR #594 的 e2e 记录。
- **验证（根治后）**：两个标签页同会话 ⇒ Network 面板 `runs/events` **仅 1 条**；关闭 leader ⇒ follower ≤3s 接管。
