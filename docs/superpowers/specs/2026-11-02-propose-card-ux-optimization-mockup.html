一、现状 vs 目标态 before / after

现状卡是「去画布吧」的传声筒，标题常为提示词复述，确认即对成本一无所知，确认后对话失联——这正是「拧巴」根源。目标态把卡片扶正为对话内的「提案预览 + 决策中枢」，并让它成为品牌三联叙事里唯一的「锚」：承接上游对话之墨，启动下游画布之落。

缺失：模型 / 提示词 / 参数 / 积分消耗 / 结果回链，以及品牌叙事。
标题常是提示词复述（与正文重复、且非节点名）→ 对话流里读完标题像复读机；确认前对「用哪个模型、花多少积分、落向哪个节点」一无所知；确认后卡片死寂，对话与画布两断。

三、长提示词处理 progressive disclosure

提示词是「证据」不是「决策控件」——确认决策不依赖读完它。模型 / 参数 / 积分始终可见、独立于提示词长度；长提示词默认单行 ellipsis，完整文本留在画布（窗口隐喻）。

五、品牌三联叙事「对话 › 锚 › 画布」

本项目的品牌内核（取自 constants/brand.ts 与锚图标计划）：用户「体内一囊墨」以自然语言流出（对话），经品牌中心动作「锚定」凝成承诺（锚＝这张卡片），再一点一滴洒在画布（画布）。对话与画布各有归属界面，唯独「锚」没有专属界面——它正是这张卡片。故卡片是传递品牌叙事的关键铰链。而本版把「锚」进一步做成可滑动的进度拇指：卡片下方的品牌轨道里，锚图标从左端「对话」一路滑向右端「画布」——抛出、滑行、落定，正是「锚定→洒在画布」的可视化。

下面这条轨道就是卡片上的品牌三联叙事：左端＝对话、右端＝画布、中央锚图标＝进度拇指。点状态按钮或拖动滑块，看锚如何「抛出 → 滑行 → 落定」；declined/expired 锚留对话端并暗化、done 画布端变绿、failed 锚卡中途抖红。

链环品牌语义卡片上的表达机制
对话「一囊墨」的自然语言流卡片之上的对话流；三联链首段「对话」在 pending 即点亮（墨已流出）
锚品牌中心动词「锚定」；Logo 本体＝锚① 引领图标＝品牌锚 glyph（anchor-generate.png）；② 主钮文案「落锚生成」；③ 锚图标即卡片品牌轨道的进度拇指——由卡片根 state-* 类驱动，沿「对话→画布」轨道滑动（pending 停在对话端 → generating 滑行 → done 落定画布）；④ 「在画布查看节点」＝拉起锚链
画布「一点一滴洒在画布」① 品牌轨道右端「画布」图标，随锚滑入 completed 变绿（墨滴落定）；② 墨滴进度替代通用条；③ completed「查看结果 ↗ 让世界记住你的模样」直接回链节点
品牌 slogan：「你体内早就有一囊墨，只是…没有找到你的锚。墨鱼π，锚定你的创意，一点一滴洒在画布，让世界记住你的模样。」——卡片在 completed 态闭合这一句，是品牌情绪落点。
