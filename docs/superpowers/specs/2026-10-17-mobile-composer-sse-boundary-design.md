# 移动端 Composer / 画布 / SSE 对话流边界重设计 — 设计规格

> 状态：**Draft — 待评审**
> 范围：**移动端 ≤767px 的 Agent 面板布局模型重构：画布 / composer 条 / SSE 对话流三者职责与三态门控**。PC 端形态不动。
> 上游：[Agent Composer UI-UX 整改规格 v0.6.0](../design/Agent%20Composer%20UI-UX%20整改规格.md)（PR #436 已合并上线）
> 关联：人工走查 12 项未过中 6 项为移动端（1-2 / 1-4 / 1-6 / 2-5 / 3-1 / 4-2）
> 日期：2026-10-17

---

## 0. 决策摘要

| # | 决策 | 说明 |
|---|------|------|
| **D-1** | **同屏合理、常驻不合理** | 「SSE 流与画布同屏」作为**按需可拉起的对话面**成立；作为每个状态都缴纳的**固定 40vh 税**不成立。恒同屏的只有「画布 + composer 条」 |
| **D-2** | **三层职责** | 画布 = 唯一主位（三态可见）；composer 条 = 恒定贴底（PR #436 已落地，不动）；SSE 流 = 按态门控 + 按需展开 |
| **D-3** | **三态默认收起 SSE 流** | 空闲 / 输入 / 生成三态下 SSE 流默认 0 高度；画布份额最大化。本规格即对此设门控状态机 |
| **D-4** | **阻塞态 = 例外门控，自动展开** | `blockingWait`（ask_user 等待作答 / propose 等待画布确认等）触发时 SSE 流自动展开至 ≤60vh；阻塞解除回到收起 |
| **D-5** | **叙事 / 协作本期不分层** | 用户拍板：先看效果再定。本期 SSE 流作为单一整体做门控；「叙事层可收起 / 协作层阻塞上浮」的双层拆分列为观察项 |
| **D-6** | **propose 确认不搬进流** | 生成提议的确认/取消继续在画布节点上做（现状即如此，保持）；SSE 流与状态行只承担「定位到画布」引导 |
| **D-7** | **全览 = 上拉 sheet（≤80vh）** | 用户主动上拉/点击展开全量对话流，松手低于阈值回弹收起；向下拽关闭。把手区触摸独占，不与画布手势互抢 |
| **D-8** | **flag 灰度，可秒回退** | 移动端门控开关关闭时回到「常驻 40vh」旧形态（保留一个版本），线上异常可即时回退 |
| **D-9** | **PC 端不动** | 本规格仅改 ≤767px 分支；PC 侧栏形态与 SSE 流常驻策略不变 |

**非目标（本期明确不做）**

- 叙事层 / 协作层拆分与独立门控（D-5，观察项 O-1）
- 「最新一条」一行锚点（观察项 O-2）
- 阻塞关键事件的通知通道（App push / 标签页角标，观察项 O-3）
- 收据召回入口（settled 后条上方常驻一行，观察项 O-4）
- composer 条自身形态调整（PR #436 已定稿）
- PC 端任何布局变更

## 1. 问题陈述

### 1.1 现象

Agent Composer 整改 v0.6.0 合并上线后，人工走查 11/23 通过；未过 12 项中 **6 项集中在移动端**：

| 走查项 | 内容 | 初步归因 |
|---|---|---|
| 1-2 / 1-4 / 1-6 | 移动端三态形态（空闲裸条 / 输入 / 生成中） | 布局模型非常驻不可见，需重定义 |
| 2-5 | 语音：按住说、松开填、不自动发 | 40vh 滚动容器与语音长按手势互抢（假设，待真机验证） |
| 3-1 | 移动端触控目标 ≥44pt | 键盘升起时「流 + 条 + 键盘」三方挤压（假设） |
| 4-2 | iOS Safari 语音与 getUserMedia 共存 | 同上，手势/焦点竞争（假设，待真机验证） |

**关键判断：这 6 项未过不是 6 个独立 bug 的概率很高，而是同一个布局模型的症状。** 先修模型，再谈验收——否则修完 4 项、冒出新 3 项。

### 1.2 现状取证（代码级，非规格自述）

- 移动端 Agent 面板 = fixed 贴底容器（z-index 70）＝ slim 顶栏 + 对话流（`agent-chat-wrap`，`max-height: 40vh` 滚动）+ composer 裸条；画布可见份额约 60%。
- 规格 v0.6.0 §5.2 明文把「对话流 40vh」定为系统层常驻——**三区同屏是常态而非例外**。
- 输入态键盘升起时，40vh 流 + 条 + 软键盘三方挤压，画布可见趋近 0。
- 对话流与 composer 位于同一 Teleport 容器，状态天然耦合（「浮层与对话流同生死」的教训刚发生过）。
- 40vh 滚动容器的自动滚动与画布拖拽 / 语音长按手势同屏竞争。

### 1.3 对标结论（三家公开产品，分级取证）

| 产品 | 流与主内容关系 | 叙事层默认 | 阻塞/确认 |
|---|---|---|---|
| WorkBuddy 小程序 | 任务卡片流即主界面（无画布） | **折叠成卡片**，完成=绿色标签 | 「等待输入」一等状态 + 就地拍板或一键终止 |
| WorkBuddy PC | 流即主界面 | 全展开 | 内联卡片在流里 |
| Dots | 左 agent 列表 + 右活动串 + 底部输入框，同屏并列 | 常驻但极简（单色行） | push 提出 + 显式批准（auto-review 三分类） |
| Codex | 移动端是**控制面**不是编辑器 | diff/输出即内容，按需看 | **系统通知 + 同意/拒绝**，不依赖停在哪个界面 |

**没有一家是「常驻 40vh 全量 SSE 流 + 画布同屏」。** lnk π 现状形态比三家都重。且三家都把阻塞确认做成「不依赖用户当前界面」的通道——lnk π 已有的 `turnStatusBar` waiting 模式（等待你作答 / 去画布确认 + 倒计时）与之互证，方向正确，缺的只是「流收起时阻塞仍可见可达」。

## 2. 目标与非目标

### 2.1 目标

1. **G-1 画布优先**：三态下画布份额最大化；SSE 流不占常驻份额。
2. **G-2 消除挤压**：输入态键盘升起时，画布不再被「流 + 键盘」双向压缩。
3. **G-3 阻塞不失联**：`blockingWait` 期间，作答/确认入口自动可见，不依赖用户主动上拉。
4. **G-4 消除手势互抢**：SSE 流收起态无滚动容器；展开后拖拽只认把手区。
5. **G-5 可回退**：flag 关闭即回到 v0.6.0 形态，不留半成品状态。

### 2.2 非目标

见 §0。重点强调：**D-5 分层不做**——用户明确「先看效果后再定」，本规格只交付「整体门控」这一层效果，分层所需的观测数据（收起态下用户是否找不到关键信息、阻塞是否失联）在灰度中收集。

## 3. 三层职责与门控状态机

### 3.1 三层职责

| 层 | 职责 | 同屏规则 |
|---|---|---|
| **画布** | 唯一主位：节点、生成结果、propose 确认交互 | **三态 + 阻塞态恒可见**（输入态被软键盘遮挡属系统限制，非设计让位） |
| **composer 条** | 恒定贴底：输入、引用入口、语音、发送/停止 | **恒同屏**（PR #436 已定稿，本规格不动） |
| **SSE 对话流** | 叙事（思考/工具/轨迹）+ 协作（ask_user 作答卡等）的**统一容器**，本期不分层 | **按态门控**：默认收起；阻塞自动展开；用户可主动上拉全览 |

### 3.2 门控状态机

```
                    ┌──────────────────────────────────────────────┐
                    │              派生输入（移动端）                 │
                    │  runPhase: idle | typing | generating | settled │
                    │  blockingWait: null | { kind, nodeId?, callId? }│
                    │  userExpand: false | true（用户主动）           │
                    └──────────────────────────────────────────────┘
                                    │
                                    ▼
        ┌───────────────┬────────────────────────┬──────────────────────┐
        │               │                        │                      │
        ▼               ▼                        ▼                      ▼
   ┌─────────┐    ┌──────────┐            ┌───────────┐         ┌───────────┐
   │ hidden  │    │  peek    │            │ expanded  │         │  (旧形态) │
   │ 0 高度  │    │ ≤60vh    │            │ ≤80vh     │         │ 常驻 40vh │
   └─────────┘    └──────────┘            └───────────┘         └───────────┘
   默认收起         阻塞例外门控              用户主动全览           flag off
```

**状态定义**

| 状态 | 高度 | 进入条件 | 退出条件 |
|---|---|---|---|
| `hidden` | 0 | 空闲 / 输入 / 生成 / settled，且无 blockingWait，且用户未主动展开 | 任一其他条件触发 |
| `peek` | ≤60vh | **blockingWait 非空**（waiting_user / propose / 批量决策等任一阻塞种类），且用户未主动展开 | blockingWait 清除 → hidden；用户主动展开 → expanded |
| `expanded` | ≤80vh | 用户主动展开（上拉把手 / 点击状态行 / 展开按钮） | 用户关闭（向下拽 /  Esc / 点击画布空白处）→ hidden；blockingWait 触发时**保持 expanded**（只升不降） |
| 旧形态（flag off） | 常驻 40vh | `mobileComposerGatedSheet = false` | flag 打开 |

**转移规则（实现以单测锁定）**

- **T1**：`blockingWait` 由 null → 非 null：`hidden → peek`（自动展开，G-3）。种类以 `turnStatusBar` waiting 模式的实际阻塞集合为准（已取证：`waiting_user` / propose 画布确认）；实施 T4 时先核对清单，凡宣告「等待用户」的阻塞一律纳入，批量类进度**不是**阻塞（它有真分母、走状态行，不触发 peek）。
- **T2**：`blockingWait` 由非 null → null：`peek → hidden`；`expanded` **保持**（用户主动看过的不强关）。
- **T3**：用户展开手势跨越阈值：`hidden ↔ expanded`；未过阈值回弹原状态。
- **T4**：`generating` 期间用户上拉 → `expanded`；回合 settled 后**保持 expanded**，由用户自行关闭（避免生成刚结束内容被瞬间抽走）。
- **T5**：输入框聚焦**不**改状态（流保持收起；键盘挤压问题由此消除，G-2）。
- **T6**：flag off 时状态机整体旁路，渲染旧常驻 40vh。

### 3.3 三态形态（验收基准图）

| 态 | 画布 | composer 条 | SSE 流 |
|---|---|---|---|
| **空闲** | 最大化 | 裸条 + 样例 chips | `hidden` |
| **输入** | 最大化（键盘升起时被系统遮挡，非设计让位） | 裸条 + 三个控件 + 引用 chips | `hidden` |
| **生成中** | 最大化 | 条 + **状态行**（约 Xs / N 积分 / 批量 N/M，已有能力） | `hidden`，可上拉 |
| **阻塞（叠加态）** | 可见 + 定位引导 | 条 + 状态行宣告「等待你作答/去画布确认」 | `peek` 自动展开 |
| **全览（用户主动）** | 露出上部 | 条常驻 | `expanded` ≤80vh，松手回弹 |

> 阻塞是**可叠加在任一态上的条件**，不是第四态。它复用所在态的画布/条形态，只改 SSE 流门控。

## 4. 交互细节

### 4.1 展开 / 收起手势

- **把手**：SSE 流收起时，条上方显示一条 24pt 高的拖拽把手（视觉上是一条 32×4 的圆角横条 + 状态行同行右侧「展开」按钮）。
- **手势区隔离**：把手区 `touch-action: none` 独占竖拖；画布手势区不变。展开后的 sheet 内部滚动只认内容区， sheet 边框/标题区不吞画布手势。
- **阈值回弹**：上拉超过 25% 可展开高度 → `expanded`；未超过 → 回弹 `hidden`。向下拽超过 25% → `hidden`；未超过 → 回弹当前高度。
- **关闭**：向下拽过阈值 / Esc / 点击画布空白处 → `hidden`。若「点击画布空白处」与画布自身交互（如取消选中）在实现期发现冲突，则仅保留下拽 + Esc 两种关闭方式，并在 PR 说明中记录。
- **动效**：height + transform 过渡 ≤240ms；`prefers-reduced-motion` 时直切。

### 4.2 阻塞例外（D-4）

- `blockingWait` 非空 → 自动 `peek`（≤60vh），流内自动滚动定位到当前阻塞卡（AskUserCard 或画布确认引导）。
- 解除后按 T2 回 `hidden`。
- **本期不做**：只把协作卡提到系统层、叙事层保持收起（D-5 分层是观察项）。
- propose 类阻塞（等待画布确认）：peek 里显示引导文案「请在画布上确认生成」+「定位到画布」按钮（现有能力，R2 不变）；确认动作本身仍在画布节点上完成（D-6）。

### 4.3 与既有能力的关系（都不是新开发，是门控集成）

| 能力 | 现状 | 本规格动作 |
|---|---|---|
| `composer-status-line` 状态行 | PR #436 已落地，显示约 Xs / N 积分 / waiting 文案 | 恒驻条上方；点击 = 用户展开入口（T3 替代触发） |
| `turnStatusBar` waiting 模式 | blockingWait 驱动，一等状态宣告 | 不变；peek 与其共存不重复（4-4 双状态面收敛为观察项） |
| 批量 N/M 进度 | node_status 逐节点回流 + done/totalTasks 真分母 | 走状态行；详情留流内（全览时看） |
| 收据行「本轮产出 N 张 · 定位到画布 / 全部保留 / 撤销本轮」 | settled 后落流末尾 | 随流收起；**召回入口不做**（观察项 O-4），全览可看 |
| 语音「按住说话」 | 裸条长按 | 不变；收起态无滚动容器，消除手势互抢假设（G-4）待真机验证 |

### 4.4 可用性

- 把手 / 展开按钮：`aria-expanded` + `aria-controls`（指向流容器 id）；聚焦态 `focus-visible` 可见（顺带修 3-4 / 4-3 的 focus 弱项）。
- peek 自动展开后，焦点移入流内阻塞卡（读屏可跟）。
- Esc 收起（4.1）；收起后焦点回到把手。
- 触控目标：把手/展开按钮 ≥44pt（3-1 验收基准；控件本体尺寸需单独核，见 §7 风险）。

## 5. 技术实现要点

### 5.1 改动落点

| 文件 / 模块 | 改动 |
|---|---|
| `apps/web/src/composables/useAgentMobileLayout.ts` | 新增（或扩展）`useMobileComposerSheet`：派生状态机（§3.2 T1–T6），纯函数 + 单测 |
| `apps/web/src/components/agent/AgentSideRail.vue` | `agent-chat-wrap` 从常驻 `max-height:40vh` 改为状态驱动高度（hidden=0 / peek≤60vh / expanded≤80vh / flag off=40vh）；条件渲染把手；接 `aria-*` |
| CSS（同文件或对应样式文件） | `.agent-panel-mobile-dock` 子选择器新增三种高度态 + 把手样式；全部走 L2/L3 设计令牌，深浅主题成对；`env(safe-area-inset-bottom)` 保持 |
| flag | `mobileComposerGatedSheet`（前端 flag，默认 on 时可配置 off 回退） |

### 5.2 约束

- **PC 零影响**：所有改动限 `isMobileLayout` 分支；共用组件的桌面路径不改一行。
- **令牌纪律**：新样式禁新增 hex/rgba 字面量；`design-token.test.ts` + `theme-usage.test.ts` 必须过。
- **`agent-chat-wrap` 高度切换**用 class 驱动而非内联 style，便于测试断言与令牌扫描。
- **状态机是纯函数**：`(runPhase, blockingWait, userExpand, flag) → sheetState`，单测穷举组合，不依赖 DOM。
- **不新引手势库**：竖拖阈值判断用原生 pointer/touch 事件（≤60 行 helper），与画布手势通过 `touch-action` 隔离。
- **高度定值**：`≤` 为上限约束；实现默认值 peek = 60vh、expanded = 80vh、旧形态 = 40vh（与 v0.6.0 一致），如需微调只改这三处常量。
- 构建后 `agent-chat-wrap` 的旧 `40vh` 字面量应仅存在于 flag-off 分支（生产取证锚点）。

### 5.3 测试矩阵

| 层 | 用例 |
|---|---|
| 单测（状态机） | T1–T6 全组合；blockingWait 种类覆盖（waiting_user / propose / 批量决策）；flag off 旁路 |
| 单测（手势） | 阈值 25% 边界：24% 回弹 / 26% 展开；向下拽对称；reduced-motion 直切 |
| 组件测试 | 三态 DOM 形态：hidden 无流节点；peek 有流且高度 ≤60vh；aria-expanded 翻转 |
| E2E（移动端视口） | 空闲无流 → 发送 → 生成中可上拉 → blockingWait 自动 peek → 解除回 hidden → settled 后 expanded 保持 |
| 令牌测试 | design-token / theme-usage 两套过 |

## 6. 验收标准（走查表 v2 输入）

| # | 验收项 | 通过标准 |
|---|---|---|
| A1 | 空闲态：画布最大化 | 无 SSE 流占位；画布可见 ≥ 视口 - 条高 |
| A2 | 输入态：键盘升起 | 画布仍露出上部；无三方挤压；条贴键盘 |
| A3 | 生成态：状态行 + 可上拉 | 约 Xs / N 积分 / 批量 N/M 可见；上拉出全览，松手回弹 |
| A4 | 阻塞自动展开 | ask_user 触发后 ≤60vh 流自动出现且定位到作答卡；解除后回收起 |
| A5 | propose 引导 | peek 显示「去画布确认」引导；确认动作在节点上完成 |
| A6 | 手势隔离 | 画布拖拽 / 语音长按 / sheet 竖拖三者不互相触发（真机） |
| A7 | 触控目标 | 把手 / 展开按钮 ≥44pt（真机） |
| A8 | 双主题 | 浅/深下把手、sheet、状态行无白块、无漏接（真机） |
| A9 | a11y | aria-expanded/controls 正确；键盘可达；peek 焦点移入阻塞卡 |
| A10 | flag 回退 | 关 flag 后恢复常驻 40vh 旧形态，无残留中间态 |
| A11 | iOS Safari 语音 | 4-2 复测：收起态下长按说话 / getUserMedia / 键盘不再互抢（真机） |

> A1–A5、A10 可桌面模拟器 + 单测/E2E 覆盖；**A6–A9、A11 必须真机**（iOS / Android 各一）。

## 7. 风险与开放问题

| # | 风险 | 缓解 |
|---|---|---|
| R-1 | AgentSideRail.vue 是 4000+ 行巨型组件，改动面集中但回归面大 | 只动移动端分支 class + 条件渲染；E2E 覆盖桌面路径不回归 |
