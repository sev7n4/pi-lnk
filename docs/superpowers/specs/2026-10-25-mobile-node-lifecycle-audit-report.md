## 7. 方法论沉淀（本次审计的可复用产出）

1. ⭐ **规格 §9（文件级改动清单）是实施排期的唯一输入** ⇒ 必须与 §12（M2 路线图）/ §10.3（走查清单）/ 实施计划**交叉核对**。
   本次实证：§9 漏列 ⇒ 计划无 Task ⇒ 实现漏做 ⇒ **三处一致地漏、无人发现**。
   ⇒ 已把这条写进规格（§9 补列说明段）。

2. ⭐ **守卫写「点名个别文件」= 给自己开后门**。V-3 原文要求扫全目录，实现只点名 2 个 ⇒ 缺口全逃过。
   ⇒ 守卫要么扫全目录、要么列全检查对象（⛔ 禁子集抽样）。

3. ⭐ **守卫判据要取「实质」不取「字面」**。V-5 原文写「图标按钮 min-width/min-height 断言」，
   但固定 `width: 44px` 同样满足命中区下限 ⇒ 判实际尺寸。⚠️ 反例也有：V-3 原文「禁裸 fixed」
   若照字面执行会误伤 FAB / 状态栏 / tab bar（它们用 fixed 是**正确**的）⇒ 判「fixed **且** 全屏」。

4. ⭐ **静态守卫的正则也会骗人**：`/top:\s*0/` 会误命中 `padding-top: 0` ⇒ 把底栏/顶栏当全屏。
   ⇒ 属性名判定要排除前缀（`(?<![-\w])top:\s*0;`）。

5. ⭐ **任何新守卫都要做变异测试**：改坏实现 ⇒ 守卫必须 EXIT=1 **且指名报错** ⇒ 证明非恒绿。
   本次对 V-3 做了（移出白名单 ⇒ 精确报出 `MobileNodeEditorSheet.vue`）。

6. ⭐ **规格自身会有内部矛盾** —— 对账时先分清「实现偏离」与「规格自相矛盾」，
   判据分层：**§4.11 结论优先于 §4/§6**；**「可验收判据」（V-x / G-x / W-x）优先于叙述性建议**。
