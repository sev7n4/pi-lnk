设计规则

  • 堆叠顺序（composer 上沿，从上到下）：后台任务卡 → 排队气泡 → composer，与 WorkBuddy 一致。
  • 展开态：标题行「N 个后台任务运行中 + 不消耗积分」+ ✕ 收起；任务行 = 状态图标 + 任务名 + 灰字状态（运行中带计时 / 已完成 / 失败红色）。已完成行保留最近 5 条供回看。
  • 收缩态：小椭圆胶囊「spinner + N 个任务运行中 · 最长 Xm Ys」；hover 浮起、点击展开。全部完成且未查看 → 变绿「✓ N 个任务已完成 · 点击查看」，查看后自动消失。
  • 自动收起：新任务开始时展开弹出；开始 5s 后或用户点 ✕ 后收为胶囊，不打扰对话。
  • 三件套不合并：dock 通知卡（系统→你，弹完即走）、排队气泡（你→agent）、后台任务卡（工具运行状态）各管各的。
  • 不加每行停止钮：run_* 在对话轮内，停 = 停整轮，走底部统一停止按钮，避免第二套停止语义。
⚠ 现实约束：pi-lnk 目前 run_*（出图 ~3min / 视频 ~11min）是同步阻塞在对话轮内的，没有独立后台任务机制。这张卡 v1 的数据源 = 对话轮内的长时工具调用状态（tool_call 开始/结束事件即可驱动）；未来若做真后台任务（detach），同款容器直接复用。
